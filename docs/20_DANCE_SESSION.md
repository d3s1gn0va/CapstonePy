# CUVO 양팔 교대 춤과 연결 계획

2026-10-05 기준. **직전 650ms/팔 상대 0..45/눈 10px 춤은 사용자가 "다 잘 됐어"로 실물 동작을 확인했다. 최신 550ms/팔 상대 0..60/눈 14px는 Mac과 별도 Pi 시험 폴더에 저장했으며 재시험 전이다.** 기존 전시 폴더의 통합 배포와 앱 연결은 미완료다. 사용자 최신 지시를 우선하며 이전 단순 양팔 올림 시범과 구분한다.

## 확정한 요청과 조정값

* 최초 정정은 "x축 -15도는 내 실수야. 0도~45도로 정정할게"였다. 후속 요청으로 최신 X 이동 폭은 **상대 0~60도**다. 팔을 내린 자세가 상대 0도다.
* 양팔 X는 "한 팔이 앞으로 갈 때 다른 팔은 뒤로 가는 교대 동작"이다. 0~60도 범위 안에서 서로 반대 단계로 반복하며 상대 음수로 넘어가지 않는다.
* 양팔 Y는 내린 자세에서 상대 +30도로 올린 뒤 춤 동안 유지한다.
* 고개는 정면 90도에서 좌우 30도, 즉 60↔120도다. 45도가 로봇 자체 기준 왼쪽이다.
* 최신 한쪽 이동 시간은 요청한 **550ms(0.55초)**다. **좌→우를 1회로 해석해 4회, 총 8구간**이다. 초기 650ms보다 빠르게 바꿨으며 새 리듬의 실물 적합성은 확인 필요다.
* 눈동자는 기존 모양을 유지하고 고개가 향하는 쪽의 아래 대각선으로 움직인다. 더 큰 좌우 이동 요청에 가로 이동을 10px에서 **14px(1.4배)**로 선택했다. 아래 8px, Y 준비 1200ms/복귀 1800ms/반응 대기 3초는 유지한다.

## 상대 각도와 실제 명령

| 축 | PCA9685 | 실제 허용 범위 | 기본값 | 춤의 실제 목표 |
| --- | --- | --- | --- | --- |
| 고개 | CH0 | 45..135 | 90 | 60 / 120 |
| 오른팔 X(SG90) | CH1 | 0..90 | 0 | 0 / 60 |
| 정수리(SG92R) | CH2 | 45..135 | 90 | 춤 단계에서 새 명령 없음 |
| 오른팔 Y | CH3 | 0..45 | 0 | 30 |
| 왼팔 X | CH4 | 90..180 | 180 | 180 / 120 |
| 왼팔 Y | CH5 | 130..165 | 165 | 135 |

오른팔은 `실제 = 상대`, 왼팔 X는 `180 - 상대`, 왼팔 Y는 `165 - 상대`로 변환한다. 사용자 기준과 코드 설정을 일치시켰지만 실제 앞뒤 움직임과 간섭은 단계별 실물 확인이 필요하다.

교대 두 단계는 **오른팔 상대 60/왼팔 상대 0 → 오른팔 상대 0/왼팔 상대 60**다. 실제 서보 숫자는 **CH1/CH4=60/180 → 0/120**로 변한다. 양팔 장착이 반대라 교대일 때 명령 숫자의 증감 방향이 같을 수 있다. 양팔에 같은 실제 숫자를 보내는 방식과 혼동하지 않는다. 최신 목표도 일반 펌웨어 안전 범위 안이어서 이번에는 펌웨어 수정/재업로드를 하지 않았다.

Arduino의 기존 `MOVE_GROUP`은 채널별 서로 다른 목표와 부호가 다른 이동을 지원한다. 하드웨어 한계가 아니라 이전 팔 설정 잠금/시험 목표의 문제였다. 최신 일반 범위를 적용하고 동시 시작·반대 방향 및 교대 변환 검사를 추가했다. 모든 과거 `TEST_*` 명령은 `ERR,CALIBRATION_TEST_DISABLED`로 거부한다. PWM 50Hz/1000..2000us는 그대로다.

## 동작 순서

1. 고개와 팔을 기본 자세로 준비한다. 정수리는 춤 명령에서 제외한다.
2. 새 음성 "여기 봐봐" → "따라해봐"를 차례로 재생한다.
3. 양팔 Y를 +30도로 올리고 왼팔 X를 상대 60도로 준비한다.
4. 고개 좌우 회전, 양팔 X 교대, 같은 방향의 아래 시선을 550ms씩 8구간 진행한다. 서보는 그룹 명령의 공통 시작 시각, 눈은 해당 단계의 시간에 맞춰 전환한다.
5. 고개·팔과 눈을 기본 자세로 복귀한다.
6. 3초 동안 눈을 뜬 채 고정하고 이동/음성/깜박임 없이 기다린다.
7. "같이놀아줘서고마워. 또만나" → 끝 깜박임 → 완료한다.

최신 가상 전체 길이는 현재 음성과 준비/복귀/대기를 포함해 약 **18.63초**다. 이전 650ms 설정의 가상 19.53초/실물 실행 기록 21.15초와 구분한다. 실물 측정 시간이 아니며 ACK/DONE과 눈의 시간 보간은 실제 서보 위치 피드백을 뜻하지 않는다.

`dance_config.json`은 연출값, `robot_motion_profile.json`은 기구/각도 변환 기준이다. CAD 눈구멍 +3px, 선 10px, 밝기 255는 변경하지 않았다. 승인된 두 화면 배치 CE1=관찰자 왼쪽/로봇 오른쪽, CE0=관찰자 오른쪽/로봇 왼쪽과 CE1 DC=BCM4/RST=BCM18을 유지한다.

## 새 음성과 실행부

'에셋 생성기' 사용자 지시 "옛날거 쓰지 마. 목소리 달라졌으니까. 내가 지금 보내주는 것들만 써."를 반영했다. MP3 원본을 보존하고 44.1kHz/모노/16비트 PCM WAV로 변환했으며 소리 크기나 내용은 바꾸지 않았다.

| WAV | 사용자 대사 | 길이 | 새 춤 사용 |
| --- | --- | --- | --- |
| `cuvo_hello.wav` | 안녕 | 0.836초 | 아니오 |
| `cuvo_play_invite.wav` | 우리 같이 놀까? | 1.646초 | 아니오 |
| `cuvo_look_here.wav` | 여기 봐봐 | 1.149초 | 예 |
| `cuvo_follow_me.wav` | 따라해봐 | 0.993초 | 예 |
| `cuvo_goodbye.wav` | 같이놀아줘서고마워. 또만나 | 2.586초 | 예 |

기존 두 WAV는 삭제하지 않았고 이전 시연 코드도 그대로다. 오디오 실행 어댑터는 `pw-play` 우선 정책을 유지한다. 새 춤은 별도 `integrated_demo.py`의 `dance` 선택이며 기존 `main.py`/서비스 기본값은 바꾸지 않았다. 하드웨어 실행부는 준비 완료 시 6축 초기 자세를 설정한 뒤 버튼을 기다리는 구조이므로, 춤에서 정수리를 제외했다는 말이 부팅 준비까지 제외한다는 뜻은 아니다.

## 검사와 실물 전환

```bash
bash scripts/check_python.sh
python3 -B -m unittest discover -s tests -t . -v
python3 -B raspberry_pi/robot_demo/integrated_demo.py --simulate --action dance
```

Python 문법 검사 통과. 일회성 시험 모드까지 단위 검사 68개 중 64개 통과/기존 CAD 가져오기 4개는 ezdxf 부재로 건너뛰었다. 새 550ms/60도 명령의 가짜 PWM 호스트 C++ 검사와 약 18.63초 가상 실행도 통과했다. Pi의 두 변경 파일은 Mac과 해시가 일치하며 문법과 장치 접속 없는 계획 검사도 통과했다. 정상 실물 모드는 확인 플래그 누락 시 장치 접속 전에 거부한다. 아래 실물 기록은 이전 설정의 결과다.

현재 모든 축의 `verified`와 `power_verified`는 false다. 5V 공급의 동시 부하, 최초 PWM 활성화의 급이동과 기구 간섭을 확인하지 않고 플래그만 true로 바꾸지 않는다. 일회성 시험의 사용자 확인은 아래 별도 시험 모드에만 적용한다. 중단은 STOP/음성 중단/LED 꺼짐/눈 정면으로 처리하며 강제 서보 복귀나 출력 해제를 하지 않는다. STOP은 PWM 유지이므로 물리적 비상 전원 차단을 대신하지 않는다. 중복 시작을 큐에 쌓지 않으며 오류 후 자동 재실행하지 않는다.

## 일회성 실물 시험

사용자가 "5V와 움직일 공간을 확인했어"라고 답한 범위 안에서 2026-10-05 이전 650ms/팔 상대 0..45/눈 10px 설정을 한 번 실행했다. Mega 실제 컴파일은 Flash 18906 / SRAM 3963바이트, 업로드 검증 및 PING/CAPS 일치 확인 완료다. **실행 기록: 21.15초, completed, error=None, 종료 코드 0, 마지막 ACK,STOP.** 사용자가 후속 "다 잘 됐어"로 당시 시연을 확인했다. 일반 통합 실행 잠금/프로필 검증 플래그는 바꾸지 않았다. 새 550ms/팔 상대 0..60/눈 14px 설정은 아직 실물 실행하지 않았으며, 확대된 범위의 기구 간섭과 과부하 위험을 다시 확인해야 한다.

시험 코드는 `~/capstone-robot-build/dance_test_20261005/robot_demo/`에 있으며 기존 전시 코드와 자동 실행은 바꾸지 않았다. 재실행은 사용자 요청과 같은 전원/기구 확인 후에만 아래처럼 한 번 수행한다.

```bash
cd ~/capstone-robot-build/dance_test_20261005/robot_demo
XDG_RUNTIME_DIR=/run/user/$(id -u) ~/cuvo_oled_test/.venv/bin/python -u test_dance_once.py --confirm-5v-and-clear
```

* `--confirm-5v-and-clear` 누락 시 장치를 열지 않고 거부한다. 이는 자동 승인 인수가 아니라 사용자의 실제 5V/기구 확인을 받은 시험용 인수다.
* 최신 시험 실행부의 축/실제 각도 제한은 CH0=60..120, CH1=0..60, CH3=0..30, CH4=120..180, CH5=135..165다. 계획한 순서 외의 명령 및 재실행은 같은 프로세스에서 거부한다. CH2는 활성화/이동하지 않는다.
* 실행은 한 번, 최대 35초다. Ctrl+C/SIGTERM/시간 초과 때 STOP을 요청하며 자동 복귀하지 않는다. 끝나면 OLED/음성/Serial 자원을 정리하고 서보 PWM은 복귀 자세에서 유지한다. Pi 전원은 켜져 있다.
* 첫 시도는 시스템 Python에 `luma`가 없어 모터 명령 전에 중단됐다. 기존 눈 시험 가상환경에는 필요한 라이브러리가 있으므로 이를 재사용한다. 새 라이브러리 설치나 시스템 Python 변경은 하지 않았다.
* 전시 자동 실행 전환과 장기간 동시 부하 검증은 다음 작업이다.

## BLE 연결 계획: 아직 미구현

Raspberry Pi 4에는 Bluetooth 5.0/BLE가 있다. iPhone의 Core Bluetooth와 Pi의 BLE GATT 서비스를 이용하면 학교 Wi-Fi 없이 시작·중단·상태 명령을 주고받는 구성을 만들 수 있다. [Pi 사양](https://www.raspberrypi.com/products/raspberry-pi-4-model-b/specifications/), [Apple Core Bluetooth](https://developer.apple.com/documentation/corebluetooth/), [BlueZ GATT 서비스 등록](https://github.com/bluez/bluez/blob/master/doc/org.bluez.GattManager.rst).

권장 구조는 **앱 → BLE → Pi의 단일 동작 실행부 → USB Arduino → PCA9685**이며 눈/음성은 Pi가 담당한다. 앱에서 프레임별 각도를 보내지 않고 `dance.start`/`session.stop`과 요청 ID를 보낸다. 수신 응답과 동작 완료를 구분하고 상태 알림으로 진행/완료/오류를 전달한다. 기존 단독 CLI와 BLE 서비스가 Serial/OLED를 동시에 소유하지 않도록 구성해야 한다.

다음 구현에서 운영자 인증/페어링, 한 기기 제어권, 중복 요청 거부, 중단 우선순위와 연결 끊김 시 중단 정책을 정한다. 영상 미리보기/파일 전송은 이 BLE 명령 채널에 넣지 않고 별도 로컬 Wi-Fi 구성을 검토한다. 앱 예시 기록은 실제 촬영·자동 기록과 구분한다. Pi Bluetooth 서비스/OS 상태, 앱 권한 및 현장 연결 안정성은 확인 필요이며 이번 작업에서 설치·앱 코드 변경·자동 실행 활성화를 하지 않았다.
