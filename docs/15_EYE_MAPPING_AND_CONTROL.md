# CUVO 눈구멍 매핑과 연동 구조

2026-10-05 업데이트: [별도 로봇 동작 통합](19_ROBOT_INTEGRATION.md)에서 기존 `EyeController`/`EyePose`를 상위 타임라인에 연결했다. 아래의 향후 연동 설명은 초기 설계 기록이다. 새 통합 코드는 미배포이고 팔 각도/전원 확인 전 실물 실행은 잠겨 있다. 휴대폰 앱과 카메라 인식은 이번 범위에 포함하지 않았다.

## 용어와 보존할 결정

* 눈동자: 흰색으로 켜지는 그래픽. 현재 중공 타원, 94x119픽셀, 선 10픽셀, 밝기 설정 255를 유지한다.
* 눈구멍: 눈동자가 보일 수 있는 고정 영역. 실제 외장의 비대칭 윤곽으로 잘라낸다.
* 좌우: 정면 관찰자 기준. 도면은 정면 왼쪽 눈이며 오른쪽은 좌우 대칭이다. 패널 헤더는 모두 위쪽이다.
* 두 장 모두 1번 SH1107 128x128이다. 3번 패널 단독 시험과 혼동하지 않는다.
* 사용자 요청에 따라 모든 기본 실물 시험은 15초다.

## 원본 CAD와 화면 좌표

사용자 `Sketch20.dxf`의 내용은 `assets/cad_exports/eye_opening_left.dxf`에 그대로 보관한다.
DXF는 mm 단위의 V.A. 정사각형 한 개와 닫힌 눈구멍 스플라인 한 개를 포함한다.
`scripts/import_oled_aperture.py`가 사각형의 기울기를 제거하고 V.A. 왼쪽 위 원점,
x 오른쪽/y 아래쪽 좌표로 변환한다. 현재 원본의 위 왼쪽 꼭짓점은 3, 위 오른쪽은 2다.
이 번호는 해당 DXF의 꼭짓점 순서이며 새로 내보낸 파일에도 같다고 가정하지 않는다.

곡선 평탄화 허용오차는 0.01 mm, 생성한 윤곽은 103점이다.
V.A. 한 변은 28.86 mm, A.A. 한 변은 상품 자료 기준 26.86 mm다.
A.A.가 V.A. 중앙에 있다는 가정은 실물 확인이 필요하다.

```text
pixel = (va_mm - (28.86 - 26.86) / 2) * 128 / 26.86 - 0.5
```

원본 곡선의 정밀도와 실제 표시 정밀도는 다르다. 약 0.21 mm 픽셀 간격, 1비트 화면,
조립 위치 오차가 남는다. 눈구멍의 맨 아래 일부는 가정한 A.A. 밖이므로 발광할 수 없다.
마스크를 전체 화면에 맞춰 늘리거나 눈동자를 자동 축소하지 않는다.

## 반복 수정 절차

1. V.A. 사각형과 눈구멍만 있는 정면 mm 단위 DXF를 준비한다. 현재 변환기는 XY 평면의 LWPOLYLINE 사각형과 SPLINE 한 개씩을 받는다.
2. Mac의 별도 개발 환경에 `ezdxf==1.4.4`와 Pillow를 준비한다. Pi에는 CAD 변환 라이브러리를 설치하지 않는다.
3. 아래 변환 명령으로 별도 JSON을 생성하고 출처 해시와 방향을 확인한다.
4. 미리보기의 V.A.(흰색), A.A.(청록색), 눈구멍(주황색), 눈동자(흰색)를 비교한다.
5. 문법/단위 검사 후 OLED 전용 폴더에만 반영하고 15초 확인한다. 실물 합치 여부는 사용자 관찰로 기록한다.

```bash
python3 scripts/import_oled_aperture.py docs/assets/cad_exports/eye_opening_left.dxf \
  --top-left 3 --top-right 2 --output raspberry_pi/robot_demo/oled_aperture.json
bash scripts/check_python.sh
python3 -m unittest discover -s tests -p 'test_oled*.py' -v
python3 raspberry_pi/robot_demo/test_oled_pair.py --gaze --preview-dir docs/assets/eye_preview
```

`ezdxf`가 없으면 CAD 검사 4개는 건너뛴다. 변환 작업에서는 반드시 설치된 환경에서 실행하여
총 21개 검사 모두 통과했는지 확인한다. 새 JSON은 `--aperture 경로`로 기본 파일을 덮어쓰기 전에 비교할 수 있다.
눈동자 크기/두께는 `oled_pair_calibration.json`, 눈구멍 윤곽은 `oled_aperture.json`만 바꾼다.

현재 `oled_pair_calibration.json`의 `aperture_expand_px=3`으로 원본 눈구멍의 표시 영역을
바깥쪽 약 3픽셀씩 넓힌다. 반경 3픽셀 원형 이웃으로 마스크를 확장하므로 중심 기준 확대와 다르다.
화면 가장자리에서는 잘리고 반대편으로 돌아 나오지 않는다. 오른쪽 눈은 확장 후 수평 반전한다.
0이면 원본 마스크로 돌아가며 정수 0..16만 허용한다. 설정이 없는 이전 파일은 0으로 취급한다.
CAD 좌표, 눈동자, 이동/깜박임 시간은 이 여유값과 독립적이다. 실제 외장 구멍 자체가 넓어지는 것은 아니다.

## 역할 분리

| 파일 | 역할 |
| --- | --- |
| `oled_renderer.py` | 눈동자 그리기 -> 이동 -> 고정 눈구멍으로 한 번만 가리기. GPIO 접근 없음 |
| `oled_motion.py` | 경과 시간에서 `EyePose(openness, offset_x)` 계산. 대기나 하드웨어 접근 없음 |
| `oled_controller.py` | 두 OLED를 한 곳에서 소유하고 `show(pose)`로 출력. 종료 시 화면/통신 정리 |
| `test_oled_pair.py` | 현재 15초 시험, 미리보기, 인자 처리 |

시선 이동은 눈동자 폭의 0.3배인 좌우 28픽셀이다. 0.2초 이동, 0.8초 바라보기,
0.2초 정면 복귀, 0.42초 깜박임 순서다. 각 방향 출발 전 정면에서 1초 대기한다.
기본 깜박임 단독 시험의 3.42초 주기는 별도로 유지한다.

## 향후 로봇 연동

버튼, 휴대폰 앱, 카메라 인식은 향후 입력 후보이며 지금 연결된 기능이 아니다.
이 입력들을 받는 상위 제어부가 눈 움직임과 서보/음성 타임라인을 결정하고,
OLED 출력은 하나의 `EyeController`만 담당하도록 한다.
매 프레임 상위 제어부가 계산한 `EyePose`를 전달할 수 있으므로 시험 반복문을 가져다 붙일 필요가 없다.

현재는 상위 제어부, 앱, 카메라 인식, 명령 큐/중단 우선순위를 구현하지 않았다.
후속 통합 시 중복 명령, 전원 종료, 전시 중 입력 처리 정책을 먼저 정한다.
OLED 드라이버는 서보나 Arduino Serial에 접근하지 않으며 기존 `main.py`도 바꾸지 않았다.
두 눈 프로그램 사이에는 잠금이 있지만 이전 단독 OLED 시험은 같은 잠금을 쓰지 않으므로 함께 실행하지 않는다.

## 현재 확인 범위

CAD 변환 재현성, 비대칭 마스크, 눈동자 유지, 최종 한 번만 가리기, 이동/복귀/깜박임 시간,
좌우 대칭, 잘못된 설정 거부, 두 번째 패널 초기화 실패 시 정리, 중복 실행 거부를 검사한다.
사용자는 원본 CAD + 바깥쪽 3픽셀 확장 결과를 "눈구멍 지금 완벽해"라고 확인했다.
이 조합을 현재 승인된 매핑으로 보존한다. 이는 실물 육안 평가이며 A.A. 위치나 조립 오차를 계측한 결과는 아니다.
실제 Pi 테스트 결과는 [현재 상태](09_CURRENT_STATE.md)에 기록한다.
