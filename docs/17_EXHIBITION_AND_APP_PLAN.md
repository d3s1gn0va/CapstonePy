# CUVO 전시 동작과 휴대폰 앱 계획

2026-10-05 후속 구현 범위: 사용자는 **로봇 동작 통합만** 선택했다. 앱과 이 문서의 약 15초 연출은 제안으로 남겨 두고, [로봇 통합 구현/검사/대기 항목](19_ROBOT_INTEGRATION.md)을 최신 구현 상태로 참고한다. 실제 배포와 업로드는 아직 하지 않았다.

2026-10-05 제안안. 관람자가 휴대폰에서 놀이를 시작해 실제 CUVO의 눈과 몸짓을 보고, 앱에서는 예시 기록을 살펴보는 체험을 구성한다. 핵심은 모터를 개별 조작하는 것이 아니라 **놀이 시작 -> 로봇의 짧은 상호작용 -> 관찰 기록 확인**이라는 제품 경험을 전달하는 것이다.

사용자가 확정한 이번 전시 범위는 **관람자 직접 조작**과 **예시 기록**이다. 아래 동작, 메뉴, 시간, 연결 방식은 그 범위에 맞춘 설계 제안이며 승인되거나 구현된 기능으로 취급하지 않는다. 이번 작업에서는 문서만 변경한다.

## 참고 자료와 구현 범위

사용자 제공 `DESIGN.md`는 CUVO Guardian App 1.0, 2026-10-02의 제안 디자인 기준이다. 홈 / 기록 / 기기, 상태의 정확성, 다음 행동의 명료함, 흰 바탕과 CUVO 색상, 발달 점수 대신 놀이 기록을 보여주는 원칙을 참고한다. 문서에 있는 대여 운영, 의료기관 전달, 마이크, 계정 기능까지 이번 전시에서 구현한다는 뜻은 아니다.

| 구분 | 현재 확인된 내용 | 이번 계획에서의 처리 |
| --- | --- | --- |
| 제품 맥락 | 자료는 영유아 발달검진 연계형 놀이 기반 관찰 로봇과 단기 대여 서비스를 설명 | 서비스 콘셉트로 소개; 실제 운영이나 임상 효과로 단정하지 않음 |
| 서보 | 사용자 구성은 SG92R 6개, 현재 제어 코드는 3채널 | 6축 안전 자세를 먼저 정하고 단계적으로 확장 |
| 눈 | SH1107 두 장, CAD 눈구멍 + 3픽셀 확장, 깜박임/시선 이동 시험 | 승인된 매핑을 유지하고 전시 타임라인에 통합 |
| 음성 | `01_name_call.wav` 약 1.437초, `02_lets_play.wav` 약 1.907초 | 기존 파일부터 활용; 새 대사/TTS는 별도 범위 |
| 카메라 | 리본 케이블 연결 후 사용자가 영상 확인 | 전시 기본 체험에서 영상 취득/스트림/저장은 시작하지 않음 |
| 앱 | 로봇 제어 앱과 통합 명령 처리는 미구현 | 관람자용 앱과 전시자 운영 화면을 새로 설계 |
| 기록 | 사용자가 예시 기록을 선택 | 준비된 예시만 표시; 실제 관람자 기록으로 만들지 않음 |
| 마이크 | 이번 하드웨어 구성에서 확인되지 않음 | 활성 스위치나 녹음 기능을 실제 기능처럼 제공하지 않음 |

기존 3채널 시연은 코드와 WAV 길이 기준으로 약 6초다. 실행 환경의 지연을 제외한 계산이며 실물 측정값이 아니다. 제안한 약 15초 체험은 눈 표현과 반응 대기를 더한 새 시나리오다.

## 전시 체험 흐름

기본 운영은 **전시용 휴대폰 한 대를 관람자가 조작**하는 방식으로 제안한다. 앱 설치나 개인 계정 입력 없이 바로 체험할 수 있게 한다. 개인 휴대폰 QR 접속은 후속 옵션이며 여러 명의 동시 제어 문제를 해결하기 전 기본 경로로 쓰지 않는다.

1. 관람자가 홈에서 CUVO의 대기 상태와 `놀이 시작하기`를 본다.
2. 짧은 준비 화면에서 로봇이 움직인다는 안내와 예시 기록 사용을 확인한다.
3. `시작하기`를 누르면 앱은 요청 중을 표시하고 Pi가 실행을 수락한 뒤 진행 화면으로 바뀐다.
4. 약 15초 동안 눈, 고개, 팔, 음성이 하나의 놀이 흐름으로 움직인다.
5. 실제 복귀 완료 응답 이후 완료 화면에서 `예시 기록 보기`와 `다시 체험하기`를 제공한다.
6. 예시 기록에서 북마크와 메모를 체험하고 홈으로 돌아간다.

관람자의 이름, 생년월일, 영상, 음성을 기본 체험에서 수집하지 않는다. 제품의 미래 관찰 기능은 예시 자료로 설명하며 로봇이 관람자의 행동을 평가했다고 표시하지 않는다.

## 로봇 동작 시나리오

### 대기와 시작 준비

전원을 켠 뒤 기기 준비, Arduino 통신, 승인된 기본 자세, 오디오와 눈 출력 상태를 확인한 후에만 체험 가능 상태가 된다. 기존 기본 자세 동작을 이번 문서 작업에서 바꾸지 않는다. 새 어깨 축의 부팅 자세는 캘리브레이션 후 별도로 정한다.

대기에서는 눈을 뜨고 약 3~5초 간격으로 깜박이는 안을 제안한다. 고개, 팔, 정수리는 기본 자세를 유지하고 자동으로 계속 흔들지 않는다. 기본 체험에서 카메라 스트림과 녹화를 시작하지 않는다. 이것이 CSI 센서의 물리 전원 차단을 뜻하지는 않는다.

### 약 15초 놀이 체험

시간은 목표 구간이며 동작/음성 완료 이벤트에 맞춰 조정한다. 음성이나 서보 명령이 실패해도 타이머만으로 다음 단계나 성공 화면을 진행시키지 않는다.

| 목표 구간 | 로봇 표현 | 앱 표시 |
| --- | --- | --- |
| 0~2초 | 짧게 시선을 옮긴 뒤 정면 복귀와 깜박임. 몸은 대기 자세 | `CUVO가 놀이를 준비하고 있어요` |
| 2~4초 | 고개 회전과 오른팔 인사 자세를 함께 시작하며 첫 WAV 재생. 눈도 몸짓 방향에 맞춤 | `CUVO가 이름을 부르고 있어요` |
| 4~7초 | 자세를 잠깐 유지하며 눈을 뜬 상태로 기다림 | `잠깐 반응을 기다리고 있어요` |
| 7~10초 | 두 번째 WAV 재생. 새 6축 구성에서는 왼팔을 포함한 짧은 초대 몸짓 제안 | `함께 놀자고 제안하고 있어요` |
| 10~12초 | 고개와 사용한 팔을 승인된 기본 자세로 천천히 복귀 | `기본 자세로 돌아가고 있어요` |
| 12~15초 | 복귀 완료 후 정면 눈과 한 번의 깜박임, 짧은 마무리 | `체험을 마쳤어요` |

몸짓은 **인사 자세 / 초대 자세 / 기본 자세**라는 이름으로 관리한다. 어깨 X/Y가 실제 어느 방향으로 회전하는지 확인되기 전 각도를 임의 지정하지 않는다. 기존 고개 0->70->0, 기존 오른팔 90->180->90도는 현재 3채널 설정이며 새 어깨 네 축의 안전 자세가 아니다.

현재의 고개/오른팔 동시 시작은 유지할 방향이다. 새 팔 두 축은 검증된 자세에 필요한 축만 사용한다. 전원과 기구 부하를 검증하기 전 서보 여섯 개를 동시에 크게 움직이지 않는다. 전원 조건은 [전체 배선 계획](16_FULL_SYSTEM_WIRING_PLAN.md)을 따른다.

정수리 카메라 회전은 이 놀이에서 중앙을 유지한다. 별도 기기 체험으로 제공하며 카메라 방향을 움직이는 것이 사람을 자동 인식/추적하는 것처럼 보이지 않게 한다. 반응 대기는 정해진 기다림이지 아이의 반응을 인식한 결과가 아니다.

첫 WAV의 대사는 현재 코드 주석상 `지우야~`다. 예시 프로필을 쓴다면 고정 녹음과 맞추고, 사용자가 앱에서 이름을 바꿨다고 음성이 그 이름으로 바뀌는 것처럼 만들지 않는다.

### 추가로 제공할 짧은 체험

* 눈 표현: 정면 / 깜박임 / 좌우 보기. 기존 승인된 타원과 눈구멍을 유지한다. 웃는 눈 등 새 표정은 승인 후 추가한다.
* 카메라 방향: 왼쪽 / 중앙 / 오른쪽의 검증된 프리셋. 고개와 팔은 고정하며 한 번의 동작 후 대기한다. 각도 슬라이더는 제공하지 않는다.
* 양팔 몸짓: 준비된 `인사` 또는 `초대` 하나를 실행하고 복귀한다. 네 축 자세와 전원 검증 후에만 노출한다.

이 항목은 로봇이 대기 중일 때만 사용할 수 있다. 일반 관람자 화면에 캘리브레이션, PWM, 임의 각도, 전체 범위 이동, 펌웨어 업로드 메뉴를 넣지 않는다.

## 앱 메뉴와 화면

하단 탭은 `홈 / 기록 / 기기`를 유지한다. 운영자 도구는 별도 권한이 필요한 `전시 운영` 화면으로 분리한다.

| 메뉴 | 관람자에게 보이는 내용 | 주요 행동 |
| --- | --- | --- |
| 홈 | 전시 체험 표시, 실제 로봇 연결/동작 상태, `같이 놀자` 한 가지 놀이, 최근 예시 기록 | 놀이 시작, 예시 기록 보기 |
| 기록 | 상단의 `예시 기록` 표시, 준비된 클립 목록, 날짜/놀이 설명 | 예시 영상 열기, 북마크, 메모 |
| 기기 | CUVO 연결 상태, 눈/몸짓 체험, 카메라 방향 조작, 촬영/저장 사용 여부 | 검증된 짧은 동작 실행 |
| 전시 운영 | 준비 점검, 오류, 반복 운용, 체험 초기화, 안전 종료 | 전시자만 접근; 관람자에게 종료/재시작 권한 없음 |

### 홈에서 완료까지

```text
홈
  -> 놀이 준비
  -> 시작 요청 중
  -> 놀이 진행 [현재 단계 + 중단]
  -> 기본 자세 복귀
  -> 체험 완료
       -> 예시 기록 상세
       -> 다시 체험하기 -> 놀이 준비
```

홈의 첫 화면에는 연결 상태와 놀이 시작이 보여야 한다. 대여 기간, 사용자 프로필, 여러 설정은 체험 시작을 밀어내지 않는다. 예시 대여 정보가 제품 설명에 필요하면 기기의 서비스 소개에 배치하고 `서비스 예시`로 표시한다.

준비 화면은 로봇 주변에 손이나 물건을 놓지 않는 짧은 안내와 약 15초 예상 시간을 보여준다. 놀이 실행 중에는 하단에 `중단`을 계속 제공한다. 탭을 옮기더라도 진행 상태와 중단 진입점을 놓치지 않는다.

완료 화면은 `체험을 마쳤어요`라고 표시한다. 실제 저장을 하지 않으므로 `놀이를 녹화했어요`, `기록을 저장했어요`라고 쓰지 않는다. 예시 기록은 방금 체험에서 생성된 것처럼 시간이나 썸네일을 갱신하지 않는다.

### 예시 기록 상세

목록과 영상 상세 모두에 `예시 기록`을 표시한다. 영상은 자동 재생하지 않는다. 준비된 승인 자료를 쓰며, 아직 자료가 없으면 예시 자료 준비 전 상태를 보여준다. 다른 아이의 영상이나 새로 생성한 아이 영상을 실제 관찰 기록으로 채우지 않는다.

북마크와 메모는 이번 체험 세션 안에서만 사용하고 다음 관람자에게 남지 않게 초기화하는 안을 제안한다. 자유 입력 메모에는 개인정보를 입력하지 않도록 안내한다. 원본 예시 영상의 영구 삭제나 의료기관 전송은 체험 메뉴에 넣지 않는다.

발달 점수, 정상/위험 등급, 자동 진단, 병원 전달 완료, 실제 대여 기간처럼 근거가 필요한 값을 만들지 않는다. 미래 서비스 설명과 현재 작동 상태를 구분한다.

### 기기와 전시 운영

기기는 관람자가 얼굴 표현과 카메라 방향을 탐색하는 보조 화면이다. `카메라 방향`과 `영상 취득/저장`을 별도 항목으로 표시한다. 지금 LED는 카메라 서보 이동 표시이며 녹화 표시로 사용하지 않는다. 마이크는 확인되지 않은 장치라 실제 켜짐/꺼짐 스위치를 제공하지 않는다.

전시 운영 화면에는 연결 확인, 시연 준비 상태, 오류 확인, 체험 메모 초기화, 중단 후 복귀 점검, Pi 안전 종료를 둔다. 잠금과 접근 권한은 구현 전에 정한다. 단순히 메뉴를 숨기는 것을 보안으로 취급하지 않는다.

## 명령과 안전 상태

관람자 앱, 물리 전시 버튼, 눈 출력, 음성, Arduino 명령은 Pi의 하나의 상위 제어부가 관리해야 한다. 앱이 OLED나 Serial을 따로 점유하거나 여러 시험 프로세스를 띄우는 방식으로 연결하지 않는다. 명령은 숫자 각도보다 `놀이 시작`, `눈 깜박임`, `카메라 왼쪽` 같은 허용된 행동 단위로 받는다.

현재 `main.py`는 동작 응답, 음성 완료, 시간 대기를 기다리는 구조다. 웹 화면에서 이 함수를 호출하는 것만으로 중단 기능이 생기지 않는다. 후속 구현에서는 취소 가능한 타임라인과 중단 우선순위, Serial 단일 소유, 명령 완료 확인을 함께 설계한다. 눈의 좌우는 정면 관찰자 기준이고 팔의 좌우는 로봇 기준이므로 시선/고개 방향을 연동할 때 좌표 기준도 실물에서 맞춘다.

| 상황 | 제안 처리 |
| --- | --- |
| 실행 중 시작을 다시 누름 | 새 동작을 거부하고 `체험 중` 표시; 나중에 실행할 명령을 쌓지 않음 |
| 앱과 물리 버튼이 동시에 시작 요청 | Pi가 첫 유효 요청 한 개만 수락 |
| 앱이 시작 요청의 결과를 받지 못함 | 같은 요청을 중복 실행하지 않고 현재 상태를 조회 |
| 사용자 중단 | 음성과 타임라인을 취소하고 Arduino STOP 요청; 확인 후 중단 상태 표시 |
| 중단 후 | 자동 복귀나 자동 재시작 금지; 전시자가 간섭 여부를 보고 별도 복귀 |
| 앱 연결 끊김 | 진행 상태를 알 수 없음으로 표시; 앱으로 시작한 동작은 제어 연결 감시 정책으로 중단하도록 구현 |
| 연결 복구 | 상태만 다시 확인; 전에 누른 시작 명령을 재전송하지 않음 |
| Arduino 통신 오류 | 신규 동작 차단, 가능한 경우 STOP; 실제 정지가 확인되지 않으면 정지 완료라고 표시하지 않음 |
| 관람자가 떠남 | 로봇 대기 상태일 때만 일정 무입력 시간 후 홈/예시 메모 초기화; 진행 중 임의 화면 초기화 금지 |

현재 Arduino `STOP`은 이동을 멈추고 PWM은 유지한다. `DISABLE`은 PWM을 끄므로 팔이 떨어질 수 있다. 관람자 중단 버튼을 무조건 DISABLE이나 기본 자세 이동에 연결하지 않는다. STOP 자체도 기계식 안전 장치나 전원 차단을 대체하지 않는다.

현재 서보는 실제 각도를 앱에 돌려주는 피드백 장치가 확인되지 않았다. `DONE`은 컨트롤러의 이동 처리 완료이지 기구물의 실제 각도나 충돌 없음이 계측됐다는 뜻이 아니다. 동작 도중 손을 넣지 않는 전시 배치와 전시자가 접근할 수 있는 서보 전원 차단 수단이 필요하다.

안전 종료 버튼은 Pi OS 종료 요청이며 전체 전원 차단이 아니다. 철수 때는 안전 종료 완료 후 Pi와 서보 전원을 끈다. 운영자 Pi 종료 기능에는 확인 절차를 둔다.

## 연결 방식과 화면 표현

**인터넷 없이 동작하는 로봇**과 **휴대폰을 연결할 로컬 통신**을 구분한다. 기존 물리 버튼 시연은 앱/네트워크가 없어도 독립적으로 작동하는 목표를 유지한다. 앱으로 실제 로봇을 조작하려면 별도 통신 연결이 필요하다.

전시용 휴대폰과 Pi를 전용 로컬 Wi-Fi에 연결하고 Pi가 제공하는 모바일 웹 화면으로 조작하는 안을 우선 제안한다. 인터넷이나 외부 클라우드에 의존하지 않도록 한다. 전용 공유기 또는 Pi 자체 접속망 중 어느 방식으로 구성할지는 현장 조건 확인 후 정한다. 아직 어느 방식도 설치/검증하지 않았다.

앱은 전시 제어자 한 명에게만 제어 권한을 주고 다른 접속은 관람 전용 또는 대기 상태로 둔다. QR만 안다고 누구나 위험 명령을 보낼 수 있게 만들지 않는다. 페어링/권한 값은 공개 저장소에 넣지 않는다.

화면은 `DESIGN.md`의 흰 바탕, 하늘색 주요 조작, 소량의 크림/오렌지, Pretendard, 짧은 존댓말을 참고한다. 큰 제품 이미지나 장식보다 놀이 시작, 로봇 상태, 중단이 먼저 보이게 한다. 상태는 색만이 아니라 문장과 아이콘으로 표시하고, 터치 영역은 48 이상을 목표로 한다.

대기 / 요청 중 / 실행 중 / 복귀 중 / 완료 / 중단 / 오류를 구분한다. 앱 애니메이션이나 예상 시간만으로 연결, 동작, 저장 성공을 만들지 않는다. 실제 연결을 확인하기 전에는 앱 화면만 시연하는 모드도 `화면 예시`로 분리한다.

## 구현 순서와 완료 기준

1. **안전 기초 확정:** 전원 용량, 양팔 X/Y의 기구 역할, 여섯 축 중립/범위, 케이블 간섭을 확인한다. 배선 계획이 아직 구현 완료 상태가 아님을 유지한다.
2. **기존 기능으로 최소 체험:** 모바일 홈 -> 기존 3채널 놀이 시작 -> 상태/중단 -> 완료, 예시 기록 목록/상세부터 연결한다. 기존 시연은 약 6초이며 약 15초 목표는 별도 타임라인을 구현한 뒤 검증한다.
3. **눈 통합:** 별도 시험 반복문이 아니라 상위 타임라인에서 승인된 눈 표현을 실행한다. 눈 매핑은 바꾸지 않는다.
4. **6축 몸짓 확장:** 새 팔 자세를 개별 검증하고 인사/초대 몸짓에 추가한다. 필요 시 Arduino를 변경하되 실제 업로드는 별도 명시 승인 후 진행한다.
5. **전시 운영 마무리:** 한 명 제어, 중복 시작 차단, 연결 끊김, 중단, 초기화, 운영자 권한, 로컬망, 안전 종료를 실물로 확인한다.

완료 확인 항목:

* 관람자가 설명 없이 홈에서 체험을 시작하고 예시 기록까지 갈 수 있다.
* 앱의 진행/완료가 Pi와 컨트롤러 이벤트에 맞으며 시작을 여러 번 눌러도 한 번만 실행된다.
* 중단과 연결 끊김을 시험하고, 확인되지 않은 정지/복귀를 완료로 표시하지 않는다.
* 실제 관람자 영상/음성을 저장하지 않으며 모든 예시 기록에 표기가 남아 있다.
* 다음 관람자에게 이전 메모와 상태가 남지 않는다.
* 인터넷이 없어도 전시가 가능하고 앱이 없어도 물리 버튼 시연은 유지된다.
* 작은 화면에서 중단 버튼과 탭이 가려지지 않으며 실물 동작과 안전 거리가 확인된다.

아직 정할 사항은 실제 전시 공간/관람자 동선, 사용 휴대폰, 로컬망 장비, 예시 영상과 사용 권한, 어깨 자세, 최종 대사, 운영자 권한 방식이다. 계획 확정 후 화면 설계와 코드 구현을 각각 진행한다.

제품 이미지, 예시 영상, 음성, 눈 표현, 폰트와 아이콘의 준비 상태는 [에셋 준비 목록](18_ASSET_CHECKLIST.md)을 따른다.
