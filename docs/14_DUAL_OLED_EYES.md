# CUVO 두 눈: 눈구멍 정렬 및 깜박임 시험

## 대상과 범위

2026-09-29 기준 두 장 모두 1번 제품인 SH1107 128x128 SPI 패널이다.
사용자 확인: 도면은 **정면에서 본 왼쪽 눈**, 오른쪽은 좌우 대칭이며 두 패널의 핀 헤더는 위쪽이다.
2026-10-05 사용자 실물 확인에 따라 출력 배치는 **CE1=정면 관찰자 왼쪽(로봇 자신의 오른쪽), CE0=정면 관찰자 오른쪽(로봇 자신의 왼쪽)**으로 저장한다. 기존 반대 배치에서는 한쪽이 보이지 않았고 `--swap-displays` 시험에 사용자가 "오 된다. 지금 설정이 맞아."라고 확인했다. 화면 배치 교환과 시선 이동 방향의 정의는 별개다.

기존 전시 프로그램, 서보, Arduino, 자동 실행 설정은 변경하지 않는다.
3번 패널의 승인된 단독 시험 `test_oled.py` / `run_oled_portrait_test.sh`도 보존한다.
이번 기능은 두 눈 독립 시험이며 전시 시퀀스와 아직 연결하지 않았다.

## 치수와 가정

사용자가 제공한 `Sketch20.dxf`를 `assets/cad_exports/eye_opening_left.dxf`에 보관했다.
V.A. 정사각형의 기울어진 좌표계를 바로잡아 왼쪽 위를 원점으로 사용한다.
**눈동자**는 흰색으로 켜지는 타원, **눈구멍**은 그 타원이 보일 수 있는 고정 영역이다.
눈구멍은 타원 근사가 아니라 DXF의 비대칭 스플라인 윤곽을 사용한다.
사용자 후속 요청으로 표시 허용 영역만 원본 경계에서 바깥쪽 약 3픽셀씩 확장한다.
`aperture_expand_px=3`이며 전체 폭/높이는 화면 경계에 닿지 않는 부분에서 약 6픽셀 커진다.
원본 CAD와 눈동자 모양은 바꾸지 않는다. 확장량 0은 원래 CAD 마스크다.
사용자가 3픽셀 확장 결과를 "눈구멍 지금 완벽해"라고 실물 확인했다. 현재 승인된 기준으로 유지한다.

| 항목 | 값 | 근거 |
| --- | --- | --- |
| V.A. 한 변 | 28.86 mm | 사용자 명시 |
| A.A. 한 변 | 26.86 mm | 앞서 제공된 1번 상품 도면 |
| A.A. 위치 | V.A. 중앙, 사방 1 mm 안쪽 | 도면 기반 가정, 실물 정렬 확인 필요 |
| 눈구멍 최소 x / y | 약 6.381 / 1.748 mm | DXF 표본 경계의 최솟값 |
| 눈구멍 최대 x / y | 약 27.591 / 28.194 mm | DXF 표본 경계의 최댓값 |
| 눈구멍 경계 표본 | 103점, 평탄화 허용오차 0.01 mm | 원본 스플라인 변환 |

최솟값/최댓값은 곡선 전체의 바운딩 박스이며 캡처의 특정 단면 치수와 같다고 가정하지 않는다.
정면 왼쪽 눈구멍의 아래 왼쪽이 더 넓은 비대칭을 보존하고, 오른쪽은 수평 반전한다.
눈구멍 아래는 가정한 A.A. 끝 27.86 mm보다 약 0.334 mm 아래다.
따라서 V.A. 전체를 128픽셀로 환산하지 않는다. 픽셀 중심 좌표 변환은 다음과 같다.

```text
pixel = (millimetres - (VA - AA) / 2) * 128 / AA - 0.5
```

왼쪽 눈동자 자체의 외곽은 x=29..122, y=7..125, 94x119픽셀로 기존 모양을 유지한다.
눈구멍과 눈동자 좌표는 별도 파일에서 관리한다. 눈구멍을 바꿔도 눈동자가 자동 변형되지 않는다.
정면 상태의 오른쪽은 픽셀 단위 수평 대칭이다.
두 화면 모두 `rotate=0`을 사용한다. 실물 상하/좌우 방향은 사용자 확인이 필요하다.
CAD의 곡선은 반영했지만 화면 픽셀 간격은 약 0.21 mm이고, A.A. 중심 위치와 조립 오차는 확인 필요다.

## 표현과 시간

- 연속선 타원, 선 두께 10픽셀. 사용자 요청 "지금의 1.7배정도"를 반영해 6 x 1.7 = 10.2를 정수 10픽셀(약 1.67배)로 맞췄다. 외곽 위치는 유지하고 안쪽으로 두꺼워진다. 도트 표현은 사용하지 않는다.
- 밝기 설정 `contrast=255`. 실제 휘도를 측정한 값은 아니다.
- 뜬 눈 3초, 닫힘 0.12초, 감은 상태 0.08초, 열림 0.22초. 한 주기 3.42초다.
- 타원을 부드러운 시간 보간으로 세로 압축하여 끝이 둥근 10픽셀 수평선으로 만든다.
- 두 눈은 같은 애니메이션 시점을 사용한다. SPI 전송 자체는 순차적이다.
- 목표 30fps이며 실제 속도는 실행 결과로 확인한다.
- 흑백 1비트 화면이므로 곡선 가장자리의 픽셀 계단은 남는다.
- 사용자 후속 요청에 따라 기본 시험 시간은 15초다. 별도 요청이 없으면 15초만 실행한다. 옵션의 기술적 상한은 120초이며 정상 종료 및 Ctrl+C/SIGTERM에 화면을 지운다.

## 좌우 시선 이동 시험

사용자 후속 요청: "좌우 이동량을 0.3배정도로 줄여도 될것같아", "복귀 했을때 눈 깜박임도 넣어줘".
별도 `--gaze` 옵션에 반영했다. 기존 기본 깜박임 시험은 유지한다.

- 타원 94x119픽셀, 선 10픽셀, 밝기 255를 유지한다. 축소나 폭 변형은 하지 않는다.
- 이동량은 `round(94 * 0.3)`인 좌/우 각각 28픽셀이다. 이전 이동량의 0.3배가 아니라 눈동자 폭의 0.3배다.
- 정면 1초 -> 왼쪽 이동 0.2초 -> 0.8초 유지 -> 정면 복귀 0.2초 -> 깜박임 0.42초 -> 오른쪽도 같은 순서. 한 주기 5.24초다.
- 출발/도착은 부드러운 시간 보간을 사용한다. 위치는 정수 픽셀이다.
- 좌우는 정면 관찰자 기준이다. 중립 눈의 대칭을 만든 **후** 두 화면에 같은 방향의 이동을 적용한다. 반대 방향으로 움직이는 눈 모임이 아니다.
- 완전한 눈동자를 먼저 옮기고 마지막에 고정 눈구멍 마스크를 한 번만 적용한다. 중립 상태에서 가려졌던 부분도 이동 후 눈구멍 안에 들어오면 보인다.
- 화면/눈구멍 밖의 픽셀은 잘리고 반대편에서 다시 나타나지 않는다. 끝 위치에서는 타원의 일부만 보일 수 있으며 임의로 축소하지 않는다.
- 시선 이동 중에는 눈을 뜨고, 매번 정면 복귀 직후 두 눈이 함께 깜박인다.
- 총 시험 시간은 15초다. 서보, 카메라, 전시 프로그램은 제어하지 않는다.

Pi 재실행:

```bash
bash ~/cuvo_oled_test/run_oled_pair_test.sh --gaze
```

설정 파일의 `gaze_width_ratio`, `gaze_move_seconds`, `gaze_hold_seconds`, `gaze_center_seconds`로 조정한다.
하드웨어 없는 미리보기는 기존 생성 명령에 `--gaze`를 추가한다.
[시선 이동 미리보기](assets/eye_preview/gaze.gif).

## 두 패널 배선

아래 숫자는 **Pi 물리 핀 번호**다. BCM 번호와 혼동하지 않는다.
재배선할 때는 Pi 안전 종료 후 Pi와 서보 전원을 모두 분리한다.

| OLED 신호 | 첫 번째 CE0 | 두 번째 CE1 |
| --- | --- | --- |
| VCC, 3.3V | 17 | 1 |
| GND | 20 | 9 |
| SDA, MOSI | 19 (BCM10) 공유 | 19 (BCM10) 공유 |
| SCL, SCLK | 23 (BCM11) 공유 | 23 (BCM11) 공유 |
| CS | 24 (BCM8) | 26 (BCM7) |
| DC | 18 (BCM24) | 7 (BCM4) |
| RST | 22 (BCM25) | 12 (BCM18) |

2026-10-05 사용자 요청으로 두 번째 CE1의 DC **36 -> 7번**, RST **37 -> 12번**, GND **30 -> 9번**으로 변경했다. 위 표는 변경 후 배선 기준이다. 첫 번째 CE0와 두 패널의 VCC/MOSI/SCLK/CS는 그대로 유지한다.

Mac/Pi 시험 폴더의 `oled_controller.py`는 CE1 DC/RST를 BCM4/18로 반영했고 파일 해시 일치를 확인했다. GND 이동에는 코드 변경이 필요 없다. 사용자가 새 핀 배선을 "맞는것같아"라고 답했고, 출력 배치를 교환한 15초 시험에서 실제 표시를 확인했다. 실물 전체 배선의 독립 계측 검증은 아니다.

저장소의 버튼/LED 및 SPI0 핀과 새 DC/RST는 겹치지 않는다. 실제 Pi에서 GPIO4의 1-Wire나 GPIO18의 I2S/PWM 등 별도 기능을 사용하고 있다면 충돌할 수 있으므로 배포 전 확인한다. 이번 작업에서는 Pi OS 설정을 확인하거나 변경하지 않았다. 물리 핀 번호는 [Raspberry Pi 공식 GPIO 안내](https://www.raspberrypi.com/documentation/computers/raspberry-pi.html#gpio-and-the-40-pin-header)를 기준으로 한다.

MOSI와 SCLK는 각각 별도의 브레드보드 연결 줄에서 분기한다. 둘을 같은 줄에 연결하지 않는다.
각 패널의 CS/DC/RST는 독립적이다. 기존 버튼 및 LED 배선은 유지한다.

## 파일과 재실행

Mac 원본은 `raspberry_pi/robot_demo/`에 있다.

- `test_oled_pair.py`: 15초 독립 시험과 하드웨어 없는 미리보기.
- `oled_renderer.py`: 눈동자 렌더링, 평행이동, 최종 눈구멍 마스크 적용.
- `oled_motion.py`: 시간에 따른 시선 위치와 깜박임 상태 계산.
- `oled_controller.py`: 두 OLED 초기화/출력/정리와 중복 실행 잠금.
- `oled_pair_calibration.json`: A.A./V.A., 눈동자 좌표, 두께, 밝기, 시간 설정(schema 2).
- `oled_aperture.json`: DXF에서 변환한 정면 왼쪽 눈구멍 윤곽과 출처(schema 1).
- `run_oled_pair_test.sh`: Pi 별도 시험 가상환경으로 실행하는 진입점.
- `tests/test_oled_pair.py`, `tests/test_oled_import.py`: 하드웨어 없는 검사와 CAD 변환 검사.

Pi 별도 폴더 `~/cuvo_oled_test/`에 런타임 Python 4개, JSON 2개, 실행 스크립트 1개를 함께 둔다.
이전 단일 파일 버전의 설정과 섞지 않는다. Pi에는 DXF나 `ezdxf` 설치가 필요 없다.
이미 준비된 `luma.oled 3.15.0`, `luma.core 2.6.0`, `RPi.GPIO 0.7.1`, Pillow 11.1.0을 사용한다.
두 SPI 장치 `/dev/spidev0.0`, `/dev/spidev0.1`과 중복 OLED 실행 여부를 먼저 확인한다.
서보 전원을 끈 상태로 OLED만 확인한다. 실행 직전 사용자가 화면을 볼 수 있게 알린다.

```bash
bash ~/cuvo_oled_test/run_oled_pair_test.sh
```

시간 옵션을 생략하면 15초 실행된다. 저장된 실행 스크립트는 승인된 배치인 `--swap-displays`를 기본으로 전달한다. 직접 Python 진입점을 실행할 때는 이 옵션을 명시해야 같은 배치가 된다. 시선 좌우는 여전히 정면 관찰자 기준이다.
중복된 두 눈 시험은 잠금으로 거부하지만, 이전 단독 시험과 동시 실행해서는 안 된다.

Mac에서 Pillow가 설치된 Python으로 아래를 실행하면 하드웨어 없이 확인할 수 있다.

```bash
python3 -m unittest discover -s tests -p test_oled_pair.py -v
python3 raspberry_pi/robot_demo/test_oled_pair.py --preview-dir docs/assets/eye_preview
```

[깜박임 미리보기](assets/eye_preview/blink.gif), [위치 도식](assets/eye_preview/calibration.png).
도식의 흰 사각형은 V.A., 청록 사각형은 A.A., 주황 곡선은 원본 CAD 눈구멍, 흰 선은 출력이다.
주황 곡선은 확장 전 원본이다. 현재 확장된 표시 영역은 `assets/eye_preview/aperture_left.png`와 `aperture_right.png`로 확인한다.
반복 보정 및 미래 연동 구조는 [15_EYE_MAPPING_AND_CONTROL.md](15_EYE_MAPPING_AND_CONTROL.md)를 따른다.

## 검증과 다음 확인

아래는 초기 시험 기록이다. 최신 변경은 CAD 윤곽 적용, 이동량 28픽셀, 복귀 후 깜박임이며
3픽셀 확장 후 문법 검사와 21개 단위 검사를 통과했다. 최신 Pi 실행 결과는 `09_CURRENT_STATE.md`의 맨 위 절을 따른다.
CAD 반영 후 Pi 시험은 15.0초, 324프레임, 평균 21.6fps, 종료 코드 0으로 완료했다.
종료 시 두 화면을 지우고 남은 시험 프로세스가 없음을 확인했다. 실물 윤곽 정렬은 사용자 확인 대기다.

- Mac Python 문법 검사, 실행 스크립트 문법 검사, 7개 단위 검사 통과.
- 51개 열림 상태의 픽셀 연결성, 눈구멍 마스크, 좌우 대칭, 감은 눈 두께와 깜박임 시간을 검사했다.
- 두 번째 패널 초기화 실패 시에도 첫 패널과 통신 자원을 정리하는 경로를 검사했다.
- Pi에 세 파일을 복사한 후 SHA-256 일치 및 Pi Python 문법 검사를 확인했다.
- 기존 단독 시험 두 파일의 SHA-256은 변경되지 않았다.
- 최초 6픽셀 Pi 30초 시험을 종료 코드 0으로 완료했다. 두 눈 묶음 654프레임, 평균 21.8fps였으며 종료 시 두 화면을 지웠다. 목표 30fps보다는 낮으므로 최종 전시 통합 시 움직임을 육안 확인한다.
- 10픽셀 변경 후 문법 및 7개 단위 검사 통과. 뜬 눈 외곽 유지와 중앙 측면 두께 10픽셀, 감은 눈 높이 10픽셀을 확인했다. 미리보기를 갱신하고 설정 파일만 Pi에 복사해 해시 일치를 확인했다. 30초 시험은 656프레임, 평균 21.9fps, 종료 코드 0이었으며 종료 시 화면을 지웠다. 두께의 실물 평가는 사용자 확인 대기다.
- 재부팅 후 10픽셀 두 눈 재시험에서 사용자가 "응. 잘 보였고"라고 실제 출력을 확인했다. 이후 시험은 15초만 실행하도록 요청했다. 기구 장착 정렬의 정밀 검증은 별도다.
