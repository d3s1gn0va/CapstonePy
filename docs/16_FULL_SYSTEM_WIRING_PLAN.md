# CUVO 전체 시스템 및 6축 서보 배선 계획

작성 기준: 2026-10-05 사용자 설명, 현재 저장소 코드, 제조사 문서.
이 문서는 배선 **계획**이며 실제 재배선, 펌웨어 반영, 전원 용량 검증을 완료했다는 기록이 아니다.

## 1. 구성과 역할

사용자가 현재 구성으로 지정한 서보는 **모두 SG92R이며 총 6개**다. 과거 문서와 코드 주석의 오른팔 MG996R 표기는 이전 구성이다.

| 부품 | 수량 | 역할 / 연결 방식 |
| --- | --- | --- |
| Raspberry Pi 4B | 1 | 버튼, 눈 표현, 카메라 영상, 음성, 전체 동작 타임라인 |
| Arduino Mega 2560 | 1 | Pi의 USB Serial 명령을 받아 서보 이동을 제어 |
| PCA9685 | 1 | Mega의 I2C 명령을 PWM 신호로 출력 |
| SG92R | 6 | 고개 1, 카메라가 달린 정수리 1, 양팔 어깨 X/Y 각 1 |
| 1번 제품 SH1107 SPI OLED | 2 | 눈 한쪽에 한 장, 128x128, 두 패널의 헤더는 위쪽 |
| 카메라 | 1 | Pi의 CSI 커넥터에 리본 케이블 연결; 정확한 센서 모델은 확인 필요 |
| USB-C PD/QC 트리거 모듈 | 1 | 어댑터와 협상한 DC 전압 출력; 모터 제어보드와 별개 |
| USB 전원 + AUX 스피커 | 1 | USB는 전원, AUX는 Pi의 음성 신호 |
| 기존 버튼 / LED | 3 / 1 | 전시, 카메라 회전, 안전 종료 / 카메라 동작 표시 |

제어 흐름:

```text
버튼 / 향후 앱 / 향후 카메라 인식
               -> Raspberry Pi 전체 타임라인
                    -> SPI -> OLED 두 장
                    -> AUX -> 스피커
                    -> USB Serial -> Mega -> I2C -> PCA9685 -> SG92R 6개
CSI 카메라 -> Raspberry Pi 영상 입력
```

앱 제어, 카메라 인식에 따른 행동, 눈과 6축 서보의 통합 타임라인은 향후 구현 항목이다.
현재 펌웨어는 고개 / 오른팔 한 축 / 카메라 회전의 **3채널만 제어**한다. 새 서보를 꽂는 것만으로 6축 동작이 추가되지 않는다.

## 2. 전원: 현재 장비의 한계와 권장 구성

사용자가 알려준 표기이며 아직 멀티미터나 부하 시험으로 확인하지 않았다.

| 장비 | 사용자 제공 사양 | 해석 |
| --- | --- | --- |
| PD/QC 트리거 모듈 | 최대 5A, 5/9/12/15/20V 순차 선택 | 5A를 새로 만들어 주는 장치가 아님 |
| 40W 어댑터 | 포트당 20W+20W 표기 | 두 포트 동시 사용 조건은 확인 필요 |
| 첫 번째 포트 | 5V 3A / 9V 2.22A | 5V에서는 최대 15W |
| 두 번째 포트 | 5V 3A / 9V 2A | 5V에서는 최대 15W, 9V에서는 18W |

**SG92R 제조사 표기는 동작 전압 4.8V다.** 일반적인 다른 서보의 6V 사양을 그대로 적용하지 않는다. 보유 제품이 5V 사용을 허용하는지 판매처 사양을 확인해야 한다. 제조사 페이지에는 전류 사양이 없으므로 여섯 개의 소비 전류를 확정할 수 없다. [TowerPro SG92R](https://towerpro.com.tw/product/sg92r-7/)

### 최종 운용 권장안

1. 기존 어댑터 포트 하나는 Pi USB-C에 연결한다. 해당 포트는 5V 출력을 사용한다. Pi 4B의 권장 전원은 3A급이며 공식 공급기는 5.1V 3A다. [Raspberry Pi 전원 안내](https://www.raspberrypi.com/documentation/computers/raspberry-pi.html)
2. 서보는 별도의 안정화된 **4.8V 전원**으로 PCA9685 `V+`에 공급한다. **5A급 출력 용량을 설계 시작점**으로 잡되, 실제 동시 동작 전류와 전압 강하를 측정해 확정한다. 5A가 실측 필요 전류이거나 충분함이 검증된 수치는 아니다.
3. 보유 SG92R의 5V 허용이 확인되면 안정화된 5V 5A급 공급기도 후보가 된다. 그렇지 않으면 4.8V로 설정 가능한 DC 전원을 선택한다.
4. 기존 어댑터의 남은 포트는 스피커 USB 전원에 사용할 수 있다. 스피커 입력 전압/전류를 확인하고 5V USB 출력만 사용한다.

이 구성에서는 서보용 전원을 추가하므로 기존 트리거 모듈을 반드시 사용할 필요는 없다. 트리거를 계속 쓰려면 더 큰 출력의 PD 전원과 적절한 강압 회로가 필요하다. **트리거 모듈 자체가 전압을 낮춰 주는 강압 회로라고 가정하지 않는다.**

4.8V 5A는 24W다. 현재 어댑터의 한 포트는 9V에서도 약 18~20W이므로 강압 회로를 추가해도 24W를 공급할 수 없다. 트리거의 12/15/20V 선택 기능 또한 어댑터가 그 전압을 지원한다는 뜻은 아니다.

### 기존 전원으로 우선 시험하는 경우

```text
기존 어댑터 포트 1 -> Pi USB-C
기존 어댑터 포트 2 -> 트리거 모듈 [5V 선택, 실측 필수]
                       -> PCA9685 V+ / GND
```

이는 보유 서보의 5V 허용 확인 후 사용하는 **제한적인 시험 후보**다. 최대 공급 전류는 어댑터 기준 3A이며 6개 동시 운용이 안정적이라고 보장하지 않는다. 적은 수의 서보부터 무부하로 시험하고, 움직이지 않는 서보도 자세 유지 전류를 사용할 수 있음을 고려한다.

스피커를 Pi USB에 꽂으려면 Mega와 스피커를 포함한 USB 장치 합계가 Pi 4의 USB 전체 전류 한도 1.2A 이내여야 한다. 스피커 소비 전류는 확인 필요다. 별도 5V USB 전원이 더 보수적인 구성이다. [Raspberry Pi USB 전원 제한](https://www.raspberrypi.com/documentation/computers/raspberry-pi.html)

### 전원 연결 금지 및 접지

* 트리거의 9/12/15/20V를 SG92R, OLED, Pi GPIO, 스피커 전원에 직접 연결하지 않는다.
* 트리거 버튼으로 전압을 바꿀 때는 서보 전원을 분리한다. 설정 후 실제 출력 전압과 극성을 먼저 측정한다.
* 서보 전원 `+` -> PCA9685 전원 단자의 `V+`, 서보 전원 `-` -> 같은 단자의 `GND`.
* 서보 전원 `+`를 Mega `5V`, Pi `5V/3.3V`, PCA9685 `VCC`에 연결하지 않는다.
* Mega `GND`와 PCA9685 `GND`를 연결해 PWM 신호 기준을 공유한다. Pi와 Mega의 접지는 USB를 통해 연결된다.
* 서보 전류의 왕복 경로는 전원과 PCA9685 사이에 직접 만든다. 브레드보드 전원 레일이나 Pi/Mega 핀을 서보 전류 통로로 쓰지 않는다.
* 공급기, 전선, 커넥터, PCA9685 실물 보드의 허용 전류를 함께 확인한다. 서보 전원 분기에 DC 차단 스위치와 배선 정격에 맞춘 퓨즈를 두는 것을 권장한다.
* 220V 쪽을 직접 배선하지 않는다. 밀폐된 인증 어댑터의 저전압 DC 출력만 다룬다.

## 3. Pi와 Mega / Mega와 PCA9685

Pi의 USB-A -> Mega의 USB-B에 **데이터 통신 가능한 케이블**을 연결한다. 이 계획에서는 Mega 전원도 USB로 공급하며 별도 VIN/DC 잭/5V 전원 공급을 병행하지 않는다.

| Arduino Mega 핀 | PCA9685 핀 | 용도 |
| --- | --- | --- |
| `5V` | `VCC` | PWM 제어 칩의 논리 전원만 공급 |
| `GND` | `GND` | 공통 신호 접지 |
| `D20 / SDA` | `SDA` | I2C 데이터 |
| `D21 / SCL` | `SCL` | I2C 클록 |

Mega와 PCA9685의 네 선 연결은 [Adafruit Mega 배선 안내](https://learn.adafruit.com/16-channel-pwm-servo-driver/hooking-it-up)를 따른다. **Mega 5V 핀으로 서보 6개의 전원을 공급하지 않는다.**

PCA9685는 Pi의 I2C 핀에 추가로 연결하지 않는다. 현재 I2C 주소 `0x40`, PWM 주파수 `50 Hz`, USB Serial 속도 `115200`을 유지하는 계획이다. `OE`는 실물 보드의 기존 연결을 유지하며 확인 없이 새 GPIO를 연결하지 않는다.

## 4. 서보 6개 채널 배치

팔의 좌우는 **로봇 자신의 기준**이다. X/Y는 사용자가 말한 축 이름이며 실제 회전 방향은 아직 확인하지 않았다.

2026-10-05 후속 지정: 오른팔의 내린 자세가 상대 0도이며 실제 서보 값은 모른다. X 상대 -45..45도, Y 상대 0..45도를 요청했고 Y는 옆으로 들어 올리는 축으로 설명했다. 채널은 CH1/CH3을 유지하되 실제 기구 방향과 기준값을 확인한 후에만 동작시킨다. 이 범위를 왼팔에 자동 적용하지 않는다.

2026-10-05 사용자가 아래 표대로 배선했다고 확인했다. 채널 배정은 통합 코드에 반영했지만 초기 자세/안전 각도/몸짓과 전원 검증은 별도다. [통합 구현](19_ROBOT_INTEGRATION.md)의 새 팔 값은 미설정으로 잠겨 있으며 실제 펌웨어 업로드나 실행 코드 배포는 아직 하지 않았다.

| PCA9685 채널 | SG92R 역할 | 배치 근거 / 상태 |
| --- | --- | --- |
| `CH0` | 고개 회전 | 기존 고개 채널 유지 |
| `CH1` | 오른쪽 어깨 X축 (임시) | 기존 오른팔 연결 유지; 실제 축 확인 필요 |
| `CH2` | 카메라가 달린 정수리 회전 | 기존 카메라 회전 채널 유지 |
| `CH3` | 오른쪽 어깨 Y축 (임시) | 새 채널 |
| `CH4` | 왼쪽 어깨 X축 (임시) | 새 채널 |
| `CH5` | 왼쪽 어깨 Y축 (임시) | 새 채널 |

기존 오른팔 축이 실제로 Y축이면 CH1/CH3의 **역할 이름**을 바꿔 확정한다. 정해지기 전 앞뒤/위아래 회전이라고 단정하지 않는다. CH6~15는 예비다. PCA9685 한 장은 최대 16채널을 지원한다. [PCA9685 채널 안내](https://learn.adafruit.com/16-channel-pwm-servo-driver/pinouts)

각 서보의 세 선은 배정된 채널에 아래처럼 연결한다.

| 서보 선 | PCA9685 해당 채널 |
| --- | --- |
| 갈색 / 검정색 | `GND` |
| 빨간색 | `V+` |
| 주황색 / 노란색 신호선 | `S / PWM` |

실물 선 색과 보드 인쇄를 확인한다. 보드의 위/아래 방향만 보고 꽂지 않는다. 채널은 **0부터** 세므로 CH0가 첫 번째, CH5가 여섯 번째 자리다. Mega의 D0~D5에 서보를 꽂는 구성이 아니다.

## 5. OLED 두 장: 최신 배선 기준

이하 Pi 숫자는 모두 **40핀 헤더의 물리 핀 번호**이며 괄호 안이 BCM 번호다.
OLED의 `SDA/SCL` 이름은 이 7핀 SPI 모델에서 각각 MOSI/SCLK를 뜻한다. Pi의 I2C SDA/SCL에 연결하지 않는다.
CE0를 정면에서 보이는 왼쪽 눈, CE1을 정면 오른쪽 눈으로 사용하는 계획이다. 실제 패널 좌우가 반대라면 기존 시험의 패널 교환 옵션으로 먼저 확인한다.

| OLED 핀 | 첫 번째 OLED / CE0 | 두 번째 OLED / CE1 |
| --- | --- | --- |
| `VCC` | Pi **17번, 3.3V** | Pi **1번, 3.3V** |
| `GND` | Pi **20번** | Pi **9번** |
| `SDA` / MOSI | Pi **19번 (BCM10)** | Pi **19번 (BCM10)** 공유 |
| `SCL` / SCLK | Pi **23번 (BCM11)** | Pi **23번 (BCM11)** 공유 |
| `CS` | Pi **24번 (BCM8)** | Pi **26번 (BCM7)** |
| `DC` | Pi **18번 (BCM24)** | Pi **7번 (BCM4)** |
| `RST` | Pi **22번 (BCM25)** | Pi **12번 (BCM18)** |

2026-10-05 사용자 요청으로 두 번째 CE1만 낮은 번호로 옮긴다: DC 36 -> 7번, RST 37 -> 12번, GND 30 -> 9번. Mac 코드와 이 표는 새 기준이며 Pi 배포/실물 변경/시험은 아직 확인하지 않았다. Pi 안전 종료 후 Pi와 서보 전원을 모두 분리하고 세 선만 옮긴다. DC/RST의 새 코드가 Pi OLED 시험 폴더에도 반영되어야 한다. 실제 Pi의 GPIO4/18 별도 기능 사용 여부는 배포 전 확인한다.

SPI MISO는 연결하지 않는다. 두 패널의 CS/DC/RST는 서로 합치지 않는다. OLED에 서보 전원이나 Mega의 5V 신호를 연결하지 않는다. 이 배치는 기존 [두 눈 배선 및 시험](14_DUAL_OLED_EYES.md)과 같다.

## 6. 카메라 / 스피커 / 기존 버튼과 LED

| 부품 | 연결 |
| --- | --- |
| 카메라 리본 케이블 | Pi의 **CAMERA / CSI** 커넥터; DISPLAY / DSI가 아님 |
| 스피커 AUX | Pi 4B의 **3.5mm 오디오/AV 잭** |
| 스피커 USB 전원 | 확인된 **5V USB 전원**; 조건 충족 시에만 Pi USB 사용 |
| 전시 버튼 | Pi **11번 (BCM17)** -> 스위치 -> GND |
| 안전 종료 버튼 | Pi **13번 (BCM27)** -> 스위치 -> GND |
| 카메라 회전 버튼 | Pi **15번 (BCM22)** -> 스위치 -> GND |
| 정수리 LED | Pi **16번 (BCM23)** -> 직렬 저항 -> LED 양극; 음극 -> **14번 GND** |

카메라는 CSI 케이블로 신호와 전원을 받는 구성이다. 별도 GPIO 전원선을 추가하지 않는다. Pi 4B의 CSI는 15핀이다. 커넥터 접점 방향은 실물에서 확인하고 전원을 분리한 상태에서 잠금 레버를 조작한다. [Raspberry Pi 커넥터 안내](https://www.raspberrypi.com/documentation/computers/raspberry-pi.html)

버튼은 현재 코드의 내부 풀업 방식이며 버튼을 통해 GPIO와 GND만 연결한다. 3.3V/5V를 버튼에 공급하지 않는다. LED의 기존 직렬 저항 유무와 값을 확인한다. 약 3V LED를 새로 배선한다면 220~330옴을 보수적인 시험 시작값으로 삼고 정격 전류를 확인한다. GPIO에 LED를 무저항으로 직결하지 않는다.

**LED의 BCM23은 물리 16번이다. OLED 클록의 물리 23번과 다른 핀이다.**
USB 전원과 AUX가 분리된 스피커를 USB 사운드카드라고 가정하지 않는다. 기존 `pw-play` 우선 재생을 유지하되 Pi의 실제 오디오 출력이 AUX로 선택되어 있는지는 이후 확인한다.

## 7. 브레드보드와 선 정리

* Pi **6번 GND**를 버튼용 GND 레일에 연결하고 버튼 세 개의 반대쪽을 그 레일에 연결한다.
* 4다리 택트 스위치는 내부에서 이미 연결된 다리 한 쌍과 누르면 연결되는 두 쌍을 구분한다. 중앙 홈을 가로질러 놓고, 필요한 경우 전원 없이 연속성 측정으로 확인한다.
* Pi **19번**을 빈 연결 줄 하나에 넣고 같은 줄에서 두 OLED의 SDA로 분기한다. Pi **23번**은 별도의 빈 줄에서 두 OLED의 SCL로 분기한다. 두 줄을 합치지 않는다.
* 3.3V와 GND는 다른 레일을 쓴다. 긴 전원 레일은 중간에서 끊어져 있을 수 있으므로 인쇄 색상만 믿지 말고 연결을 확인한다.
* 브레드보드는 버튼과 OLED 신호 분기에만 사용한다. 서보/스피커의 큰 전류를 브레드보드로 흘리지 않는다.
* 선 양끝에 `NECK`, `CROWN`, `R_X`, `R_Y`, `L_X`, `L_Y`, `OLED_CE0`, `OLED_CE1`처럼 같은 이름을 붙인다.

## 8. 기구 안전과 이후 소프트웨어

* 고개와 정수리 회전에는 CSI/OLED 배선의 여유와 고정점을 둔다. 케이블을 잡아당기거나 감아 버리지 않도록 하고 연속 360도 회전을 전제로 하지 않는다.
* 양팔 2축 구조는 안쪽 축이 바깥쪽 서보와 팔 무게까지 받는다. SG92R의 제조사 스톨 토크는 4.8V에서 2.5kgf·cm이며 연속 사용 가능한 토크 보증이 아니다. 실제 팔 길이/무게와 지지 구조를 확인한다. [SG92R 토크](https://towerpro.com.tw/product/sg92r-7/)
* 새 어깨 축의 중립 각도, 방향, 최솟값/최댓값은 각각 캘리브레이션한다. 과거 오른팔의 90->180도를 네 축에 복사하지 않는다. 좌우 대칭 자세가 같은 숫자 각도를 뜻하지도 않는다.
* 현재 코드의 펄스 폭 1000~2000us와 50Hz를 이번 계획에서 변경하지 않는다. 기구 충돌이나 과부하 경고 없이 범위를 넓히지 않는다.
* 이후 Arduino에는 6채널별 이동/안전 범위/완료 응답을, Python에는 6축 자세와 동시 동작 타임라인을 추가해야 한다. 이는 이번에 구현한 내용이 아니다.
* Pi가 눈, 음성, 서보 명령을 한 타임라인에서 관리하고 Arduino가 서보 보간을 맡는 역할 분리를 유지한다. 눈은 원본 CAD + 3픽셀 확장의 승인된 매핑을 보존한다.
* 전원 연결 직후 새 팔 네 축을 임의의 0도/90도/180도로 자동 이동시키지 않는다. 안전한 기구 중립 자세를 먼저 확정한다.
* 안전 종료 버튼은 OS를 종료할 뿐 서보 전원이나 어댑터 전원을 물리적으로 끊지 않는다. 종료 후 별도 서보 전원과 전체 전원을 끄는 절차가 필요하다.

## 9. 연결 및 확인 순서

1. Pi를 안전 종료하고 Pi / 서보 / 스피커 전원을 모두 분리한다.
2. 현재 연결을 사진과 선 라벨로 남기고 위 표의 실제 핀과 대조한다.
3. CH0/1/2를 유지하면서 새 축의 역할을 확정하고 CH3/4/5를 배정한다. 전원은 아직 공급하지 않는다.
4. 서보 없이 전원 출력 전압/극성을 측정하고, 보유 SG92R의 허용 전압과 전원 공급 용량을 확인한다.
5. 서보 전원을 분리한 채 Pi, Mega 통신, 카메라, OLED 두 장, AUX 음성을 각각 확인한다. OLED 시험은 기존 기준인 15초를 유지한다.
6. 6축용 코드와 안전 각도 검사를 준비한다. Arduino 실제 업로드는 사용자가 `Arduino 업로드 승인`이라고 명시한 경우에만 진행한다.
7. 서보혼/기구 부하를 분리하거나 안전한 상태에서 한 축씩 작은 각도로 확인한다. 큰 각도나 여섯 축 동시 동작을 첫 시험으로 쓰지 않는다.
8. 기구 중립/간섭을 확인한 뒤 점진적으로 동시 동작을 늘리고 전압 강하, 전류, 발열, 리셋, 떨림을 확인한다.
