# CUVO OLED 눈 단독 시험

## 확인된 하드웨어

- CUVO는 기존 3서보 전시 로봇의 이름이다. 별개의 로봇이 아니다.
- 사용자가 제공한 실물 사진: `1.5 GME128128-01-SPI`, `VER:3.1`, `Dots:128*128`, `IC:SH1107`.
- 7핀 헤더는 사진상 납땜되어 있다. 암-암 점퍼선으로 Pi에 연결한다.
- 이 문서는 한 장의 표정 출력 시험 기록이다. 2026-09-29 추가된 SH1107 두 눈/깜박임 시험은 [별도 문서](14_DUAL_OLED_EYES.md)를 따른다. 전시 시퀀스 통합은 아직 미구현이다.

## 배선

Pi 안전 종료 후 USB-C 및 서보 전원을 분리하고 배선한다.
OLED 뒷면이 금속이나 다른 기판에 닿지 않도록 한다.

| OLED | Pi BCM/기능 | Pi 물리 핀 |
| --- | --- | --- |
| RST | GPIO25 | 22 |
| CS | GPIO8 / CE0 | 24 |
| DC | GPIO24 | 18 |
| SDA | GPIO10 / MOSI | 19 |
| SCL | GPIO11 / SCLK | 23 |
| GND | GND | 20 |
| VCC | 3.3V | 17 |

SDA/SCL이라는 표기라도 이 모듈은 SPI다. I2C 물리 3/5번에 연결하지 않는다.
기존 버튼 GPIO17/27/22, LED GPIO23과 겹치지 않는다.
사용자가 VCC=물리17, GND=물리20 연결을 확인했으나 사진만으로 모든 선을 검증하지는 못했다.

## 소프트웨어와 실행

`raspberry_pi/robot_demo/test_oled.py`는 기존 `main.py`, Arduino 통신,
버튼, 카메라 LED를 사용하지 않는다. SPI와 GPIO24/25만 직접 제어한다.
기존 전시 프로그램은 수정하거나 재시작하지 않는다.

Pi에는 `~/cuvo_oled_test/` 아래 별도 가상환경과 시험 파일을 둔다.
의존성은 `luma.oled==3.15.0`, `RPi.GPIO==0.7.1`이다.
SPI 활성화에는 관리자 권한이 필요하다. 사용자가 Pi 터미널에서 실행:

```bash
sudo raspi-config nonint do_spi 0
ls -l /dev/spidev0.0
```

재부팅을 자동 실행하지 않는다. SPI 장치가 생성되는지 먼저 확인한다.
서보 전원을 끈 상태에서 OLED만 시험한다.

```bash
~/cuvo_oled_test/.venv/bin/python ~/cuvo_oled_test/test_oled.py
```

기본 시험은 뜬 눈, 웃는 눈, 감은 눈을 각각 2초씩 두 번 표시한 뒤 화면을 끄고 종료한다.
방향이 다르면 `--rotate 1`, `2`, `3`으로 조정한다. Ctrl+C로 중단할 수 있다.
`--preview-dir /tmp/cuvo-eye-preview`는 GPIO/SPI 접근 없이 PNG 세 장만 생성한다.
SPI 전송 성공은 실물 화면의 정상 출력을 보장하지 않으므로 사용자 육안 확인이 필요하다.

## 2026-09-21 준비 결과

- Pi의 별도 시험 폴더에 가상환경 설치와 시험 파일 복사를 완료했다.
- `bash scripts/check_python.sh` 통과, Pi에서 드라이버 import 통과(하드웨어 초기화 없음).
- 128x128 흑백 PNG 세 장의 크기, 비어 있지 않음, 서로 다른 픽셀을 검사하고 미리보기를 확인했다.
- 기존 전시 프로세스는 유지됐고 마지막 로그는 버튼 입력 대기였다.
- 사용자가 SPI를 활성화한 뒤 `dtparam=spi=on` 및 `/dev/spidev0.0`을 확인했다.
- 독립 시험을 12초간 실행했다. open/happy/closed 두 주기와 화면 지우기를 오류 없이 완료했다(종료 코드 0).
- 사용자 확인: 1번 실제 패널에도 표정이 보였고 큰 문제는 없었다. 정밀한 방향과 전체 픽셀 검사는 별도다.
- 이번 실행에서 서보 명령, 전시 프로그램 재시작 및 Arduino 변경은 수행하지 않았다.
- 가상환경은 시스템 패키지를 읽는 `--system-site-packages` 방식이다. `pip check`에서
  기존 시스템의 apt-listchanges 및 일부 타입 스텁 패키지 의존성 경고가 나왔다.
  OLED 드라이버 import와 이미지 생성은 통과했고, 관련 없는 시스템 패키지는 변경하지 않았다.

## 3번 패널 교체 시험

1.3인치 SPI 128x64 제품이다. 상품 제목은 SH1106, 상세 표는 CH1116(SH1116 호환)이다.
실물 칩 정보는 미확정이며, `--controller sh1106`은 첫 시험 후보일 뿐 호환을 보장하지 않는다.
물리 핀헤더 납땜 여부와 실물 핀 인쇄를 확인한 후, 전원을 완전히 분리한 상태로 교체한다.
두 패널을 같은 CS에 동시에 연결하지 않는다.

| 3번 OLED | Pi 물리 핀 | 기능 |
| --- | --- | --- |
| GND | 20 | GND |
| VCC 또는 VDD | 17 | 3.3V |
| SCK | 23 | GPIO11 / SPI SCLK |
| SDA | 19 | GPIO10 / SPI MOSI |
| RES | 22 | GPIO25 |
| DC | 18 | GPIO24 |
| CS | 24 | GPIO8 / CE0 |

Pi 쪽 기존 OLED 핀 배정은 유지하지만 OLED 쪽 순서는 1번과 다르다.
준비된 실행 옵션은 `test_oled.py --controller sh1106`이며 기본값 SH1107은 유지된다.
사용자가 3번 배선 완료를 알린 뒤, 수정 파일을 Pi 별도 시험 폴더에 복사했다.
`--controller sh1106`으로 open/happy/closed 두 주기(12초)를 전송하고 화면을 지운 뒤
종료 코드 0으로 완료했으나, 사용자는 화면이 보이지 않았다고 보고했다.
표시 시간을 놓쳤을 가능성을 구분하기 위해 같은 설정의 `--cycles 5`(30초) 관찰 시험을 추가했다.
30초 재시험에서 사용자가 실제 표시 성공을 확인했다. 처음에 보이지 않았던 원인은 미확정이다.
사용자의 도트 디자인 수정용 사진 촬영을 위해 같은 설정으로 30초 시험을 다시 실행했다.
다음 단계는 촬영 결과를 바탕으로 도트와 눈 형태를 조정하는 것이다.
이 결과만으로 실제 제어 칩이 SH1106이라고 확정하지 않는다.

## 2026-09-22 세로형 연속선 디자인

사용자는 패널을 세로로 장착하고 도트 대신 이어진 선을 사용하기로 했다.
`eye_image()`는 현재 타원 테두리, 둥근 아치, 끝이 둥근 수평선을 그린다.
이전 도트 시험은 과거 기록이며 현재 렌더링과 다르다.

3번 패널의 세로형 시험:

```bash
~/cuvo_oled_test/.venv/bin/python ~/cuvo_oled_test/test_oled.py --controller sh1106 --rotate 1 --cycles 5
```

논리 화면은 64x128이다. 최신 사용자 요청으로 좌우 여백 0, 선 두께 6픽셀,
밝기 설정 `contrast(255)`를 사용한다. 뜬 눈 경계는 x=0..63, y=10..117이다.
밝기 255는 소프트웨어 설정 최댓값이며 실제 휘도를 측정한 값은 아니다.
사진상 패널을 가로로 둔 상태에서는 그림이 옆으로 보인다. 반대 세로 방향은 `--rotate 3`을 사용한다.
핀을 다시 연결할 필요는 없으며, 통전 중 핀이나 기판 뒷면을 만지지 않는다.
1비트 흑백 패널이므로 도트 간 끊김은 제거하지만 회색조 안티앨리어싱은 사용하지 않는다.
기본 두 주기 12초 및 `--cycles 5` 30초 후 화면을 지우는 종료 동작은 유지한다.

문법 검사와 9개 표정/화면 크기 조합의 픽셀 연결성, 여백 및 중공 타원 검사를 통과했다.
Pi에 시험 파일을 복사하고 위 세로형 명령으로 30초 표시 후 종료 코드 0을 확인했다.
사용자는 최종 최대 밝기/전체 폭/6픽셀 디자인의 실제 결과가 괜찮다고 확인했다.
최대 밝기/전체 폭/6픽셀 수정 후에도 문법 및 9개 렌더링 조합 검사를 통과했고,
Pi의 별도 OLED 시험 파일에 반영했다. 실제 화면의 밝기와 폭은 사용자가 확인했다.
해당 설정으로 30초 시험을 실행하고 종료 코드 0 및 화면 지우기를 확인했다.
시험 후 전시 프로세스는 조회되지 않았고 최근 로봇 로그에 `ACK,PING` 시간 초과가 있었다.
이번 작업은 전시 코드를 변경하거나 재시작하지 않았으며 해당 오류의 원인은 별도 확인이 필요하다.

## 승인된 시험 재실행

2026-09-22 사용자는 "응 괜찮았어. 이렇게 일단 저장해서 다음에 내가 해달라했을때도 똑같이 테스트 실행 바로 할수있게 해주고 라즈베리파이도 꺼줘"라고 요청했다.

- 패널: 3번, SH1106 드라이버, 세로 64x128, `rotate=1`.
- 밝기 설정: 255. 좌우 여백: 0. 선 두께: 6픽셀. 뜬 눈 위아래 여백: 각 10픽셀.
- 표정: 연속선 타원, 둥근 아치, 끝이 둥근 수평선. 각 2초, 5주기, 총 30초 후 화면을 끈다.
- Mac 원본: `raspberry_pi/robot_demo/test_oled.py`, `raspberry_pi/robot_demo/run_oled_portrait_test.sh`.
- Pi 저장 위치: `~/cuvo_oled_test/`와 해당 폴더의 `.venv/`.

Pi가 켜져 있고 같은 배선/패널임을 확인한 뒤 SSH 접속하여 아래 한 줄을 실행한다.

```bash
bash ~/cuvo_oled_test/run_oled_portrait_test.sh
```

다음 에이전트는 재실행 요청을 받으면 이 설정을 임의로 다시 디자인하지 않는다.
OLED 외에 Arduino, 서보, 기존 `main.py`를 실행하거나 재시작하지 않는다.
시험 전 화면을 보도록 알리고, 실행 종료와 실제 표시 확인을 구분한다.
현재 Arduino PING 오류는 별도 문제다. OLED 시험 재실행에 이를 고칠 필요는 없다.
이 시험은 자동 부팅 기능에 등록하지 않았다. Git commit/push도 하지 않았다.
