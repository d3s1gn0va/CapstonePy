# 08 Calibration And Safety

## 수동 팔꿈치와 새 춤 미리보기 (2026-10-18)

사용자는 양팔 팔꿈치가 120..180도에서 사람이 조절해 고정하는 프리스탑임을 확인했다. 모터/채널 추가 없이 시뮬레이터의 고정 기구 파라미터로만 반영했다. 기본 미리보기는 150도이며 실제 권장/검증 각도를 뜻하지 않는다. 고정 각도를 바꾸면 어깨 하중·공간이 달라지므로 실물 전환 전에 다시 확인한다.

새 `CUVO Groove`는 로컬 시뮬레이터에서만 실행했다. 기존 프로필 범위·원점·PWM·검증 플래그와 Pi 기본 춤은 변경하지 않았다. 화면의 범위 검사/복귀 성공은 전원·기구·충돌 안전 검증이 아니다. [공유 실행 구조와 한계](22_OFFLINE_CHOREOGRAPHY_PREVIEW.md)를 따른다.

## 최신 로컬 기준 (2026-10-13)

사용자가 문제 서보 교체·새 범위의 기구 간섭 정리와 서보 전원 ON/보드 5V 선택을 확인했다. 다음 설정은 Mac과 **Pi/Arduino에 배포 완료**했으며 새 원점 이동 명령 완료와 정상 서비스 종료 복귀 경로를 확인했다. 사용자가 기본 자세의 팔 내림/정면을 관찰 확인했다. 새 지정 춤은 요청에 따라 2회 명령 완료했지만 독립 전압·전류 계측과 전체 범위 실물 시험은 하지 않았고 검증 플래그는 false다.

| 축 | 채널 | 실제 서보 명령 범위 | 상대 0 명령값 | 상대 범위 |
| --- | --- | --- | --- | --- |
| 고개 | CH0 | 45..135 | 90 | -45..45 |
| 오른팔 X | CH1 | 0..180 | 45 | -45..135 |
| 정수리 | CH2 | 45..135 | 90 | -45..45 |
| 오른팔 Y | CH3 | 0..45 | 0 | 0..45 |
| 왼팔 X | CH4 | 0..180 | 135 | -45..135 |
| 왼팔 Y | CH5 | 135..180 | 180 | 0..45 |

오른팔 X는 `45 + 상대각도`, 왼팔 X는 `135 - 상대각도`, 왼팔 Y는 `180 - 상대각도`다. 왼팔의 180->0 요청은 감소 방향이며 저장된 최소/최대는 0/180으로 정렬한다. 최신 춤 상대 0..80은 오른팔 45..125/왼팔 135..55, Y +45는 오른팔 45/왼팔 135로 변환한다. Y는 지정 범위의 상한이다. 사용자 요청 후 충돌·과부하 위험을 안내했고 이 춤 1회 명령 완료를 확인했지만 독립 부하/전체 범위 검증은 아니다. PWM 50Hz/1000..2000us는 그대로다.

새 `--home-on-start-stop`은 부팅 대기 준비와 정상 서비스 종료 때만 6축 `{0:90,1:45,2:90,3:0,4:135,5:180}`으로 복귀한다. `--confirm-5v-and-clear`, Serial 소유/잠금, 최신 펌웨어 CAPS 일치와 DONE/STOP 확인을 요구한다. 일반 앱 STOP/통신 소실/오류에서는 추가 복귀 이동을 하지 않는다. 실패한 부팅 복귀는 같은 부팅에서 자동 재시도하지 않는다. 첫 PWM은 실제 시작 위치를 알 수 없어 급이동할 수 있으며 지정한 3초가 첫 움직임 속도를 보장하지 않는다.

정상 종료에는 Pi와 서보 외부 전원이 복귀 완료까지 모두 있어야 한다. 전원선 강제 분리, 정전, OS/제어기 장애에서 복귀를 보장하지 않는다. 코드 준비와 실제 설치/동작 검증을 구분한다.

## 이전 로컬 기준 (2026-10-05)

최신 프로필/Arduino 일반 명령에 아래 값을 반영했다. 이후 Mega 컴파일/업로드 검증과 별도 Pi 시험 폴더에서 5축 춤 명령 1회를 완료했다. 사용자는 해당 시험의 5V와 이동 공간을 확인했으며, 정식 검증 플래그와 기존 전시용 폴더/자동 실행은 변경하지 않았다. [시험 결과](09_CURRENT_STATE.md)를 따른다.

| 축 | 채널 | 허용하는 실제 서보 명령 | 기본값 |
| --- | --- | --- | --- |
| 고개 | CH0 | 45..135 | 90(정면), 45가 로봇 왼쪽 |
| 오른팔 X | CH1 | 0..90 | 0(내림) |
| 정수리 | CH2 | 45..135 | 90(정면), 45가 로봇 왼쪽 |
| 오른팔 Y | CH3 | 0..45 | 0(내림) |
| 왼팔 X | CH4 | 90..180 | 180(내림) |
| 왼팔 Y | CH5 | 130..165 | 165(내림) |

위 값은 사용자 지정 기준이며 독립 계측/동시 부하 검증 완료를 뜻하지 않는다. 모든 `verified` 및 `power_verified`는 false다. 오른팔 X는 SG90, 나머지 5개는 SG92R이다. 최신 춤의 상대 X 0..60은 오른팔 실제 0..60, 왼팔 실제 180..120으로 변환한다. 상대 Y +30은 오른팔 30/왼팔 135다. 음수 X는 허용하지 않는다. 이전 0..45 춤은 사용자가 실물 동작을 확인했지만, 새 550ms/0..60 동작은 재시험 전이다. 확대된 이동 폭과 빨라진 움직임의 충돌·과부하 가능성을 확인하며, 일반 펌웨어 안전 범위/PWM은 넓히지 않았다.

* 로컬 펌웨어는 과거의 모든 `TEST_*` 끝점 명령을 거부한다. 이전 0/90/180 시험을 새 기구에 재사용하지 않는다.
* PWM 50Hz/1000..2000us는 변경하지 않았다. 첫 PWM 활성화 시 실제 시작 각도를 모르므로 급이동을 막거나 이동 속도를 보장한다고 말하지 않는다.
* 5V 3A 공급의 6축 동시 부하와 기구 간섭을 확인한 뒤에만 실행 잠금을 해제한다. 플래그를 채우는 것 자체가 검증은 아니다.
* Mac 코드 변경/가상 검사와 Pi 배포/실물 성공을 구분한다. 예전 `main.py`를 임의로 재시작하지 않는다. [춤 구현](20_DANCE_SESSION.md), [현재 상태](09_CURRENT_STATE.md)를 먼저 따른다.

## 이전 캘리브레이션 기록

이하 각도와 출력 상태는 과거 시험 당시 기록이다. 현재 운용 기준은 위 표이며, 아래의 '최신' 표현으로 이를 덮어쓰지 않는다.

최신 설정은 고개 CH0/정수리 CH2 기본 45도와 범위 0..90도, 오른팔 X CH1 기본 180도/감소 방향이다. 실제 업로드와 기본 자세 시험의 ACK/DONE을 받았지만 사용자는 **"아무것도 안움직였어"**라고 보고했다. 실제 동작 성공이나 기본 자세 검증으로 기록하지 않는다. 추가 실행 전에 외부 서보 전원/배선/출력 경로를 확인한다. 전원을 재연결하면 기존 PWM 명령으로 갑자기 움직일 수 있으므로 기구를 안전하게 지지하고 전원이 연결된 선을 바꾸지 않는다.

CH1의 잠정 상대 범위는 0..45(실제 180..135)다. 이전 -45..45 요청 중 음수 쪽은 실제 명령 180도를 넘으므로 허용하지 않는다. CH3/4/5는 미설정 잠금이다. 모든 `verified` 및 `power_verified`는 false로 유지한다. 최신 소프트웨어 상태는 CH0/1/2 ENABLED/IDLE, CH3/4/5 DISABLED/IDLE이며 각도 피드백은 없다. 전시 프로그램/버튼은 중지 상태고 예전 전시 설정과 새 펌웨어는 호환되지 않는다.

사용자 최신 업로드 지시는 "업로드 승인. 앞으로 그냥 바로 너가 업로드 해"다. 요청한 코드 변경에 필요한 업로드에는 재승인을 묻지 않되 검사/컴파일/프로그램 중지/포트 확인/업로드 검증/PING 확인을 유지한다. 이 지시로 요청하지 않은 서보 시험이나 PWM 펄스 폭 변경까지 자동 승인된 것은 아니다.

이전 90도 시험 기록: 2026-10-05 충돌/과부하 위험 안내와 사용자 승인 후 한 채널씩 6개 모두 90도 명령 ACK/DONE을 확인했다. 이후 위 0도 시험으로 마지막 출력 명령이 바뀌었다. 두 시험 모두 안전 범위나 내린 자세 확인은 아니다. [최신 상태](09_CURRENT_STATE.md)를 따른다. 전시 프로그램은 중지됐고 버튼 3개는 비활성이다. 기존 자동 실행 등록은 남아 있으므로 캘리브레이션 전 재부팅/전시 재시작을 하지 않는다.

### 새 오른팔의 상대 각도 (이전 기록, 최신은 위 절 우선)

사용자가 확인한 기준은 **팔을 내린 자세 = 상대 0도**이며 실제 서보 명령값은 모른다. 요청 범위는 오른팔 X -45..45도, Y 0..45도다. 사용자가 말한 Y는 팔을 옆으로 들어 올리는 축이다. 이 범위는 사용자 지정 기구 범위이며 실물 계측 검증 완료를 뜻하지 않는다.

통합 프로필의 `joint`는 상대 각도, 상위 `minimum`/`maximum`/`neutral`은 실제 Arduino로 보내는 0..180도다. 변환은 `servo_zero + direction * 상대 각도`이며 기준값과 방향은 측정 전 `null`로 둔다. 상대 -45도를 그대로 Arduino에 보내거나 내린 자세가 실제 0/90/180도라고 추정하지 않는다. 기준이 실제 0도라면 양 방향 -45..45도를 이 변환으로 모두 만들 수 없으므로 혼 정렬이나 기구/범위 검토가 필요하다.

오른팔 기본 자세의 목표는 내린 상태다. 아직 실제 명령값을 찾지 않았으므로 실물 초기 자세를 변경하지 않았다. 현재 팔이 올라가 있으면 전시 버튼 시험을 멈추고, 서보 전원을 분리한 상태에서 기구 간섭과 혼 정렬을 확인한다. 전원이 켜진 서보를 억지로 손으로 돌리지 않는다. 첫 PWM 활성화 때 급이동할 수 있으므로 큰 각도로 기준값을 찾지 않는다. 왼팔 설정은 별도로 확인한다.

2026-10-05 새 6축 통합에서는 팔 4축의 안전 범위/초기/몸짓 각도를 아직 모른다. 아래 기존 오른팔 90->180도와 안전 범위를 새 어깨 기구에 자동 적용하지 않는다. 새 프로필의 `null` 및 펌웨어 그룹 범위의 `-1`은 미설정 잠금이다. 각도, 기구 간섭과 전원 확인 전 실물 실행/업로드를 하지 않는다. 상세 절차는 [통합 안전 안내](19_ROBOT_INTEGRATION.md#중단과-안전)를 따른다.

`config.py` 주석에 따르면 실제 기구물을 조립한 뒤 서보 각도를 찾고, 안전 범위 안의 정수로 기록해야 한다.

배포된 기존 Raspberry Pi 전시 코드의 목표 각도(최신 통합 기준과 다르며 재시작 금지):

```text
HEAD_NEUTRAL_DEG = 0
HEAD_LEFT_DEG = 70
ARM_DOWN_DEG = 90
ARM_UP_DEG = 180
CAMERA_CENTER_DEG = 90
CAMERA_LEFT_DEG = 30
CAMERA_RIGHT_DEG = 150
```

## 안전 범위

Raspberry Pi:

```text
HEAD_SAFE_MIN_DEG = 0
HEAD_SAFE_MAX_DEG = 180
ARM_SAFE_MIN_DEG = 70
ARM_SAFE_MAX_DEG = 180
CAMERA_SAFE_MIN_DEG = 30
CAMERA_SAFE_MAX_DEG = 150
```

이전 Arduino 범위(현재 값은 고개/정수리 0..90, 오른팔 X 135..180):

```text
HEAD_SAFE_MIN_DEG = 0
HEAD_SAFE_MAX_DEG = 180
ARM_SAFE_MIN_DEG = 60
ARM_SAFE_MAX_DEG = 180
CAMERA_SAFE_MIN_DEG = 30
CAMERA_SAFE_MAX_DEG = 150
```

위 기존 Pi의 팔 기본 90도와 정수리 목표 150도는 최신 Arduino 범위 밖이다. 기존 프로그램을 재시작하지 않는다. 큰 각도 시험은 기구물 충돌 가능성을 반드시 확인해야 한다.

## PWM 펄스 폭

Arduino:

```text
SERVO_MIN_PULSE_US = 1000
SERVO_MAX_PULSE_US = 2000
```

PWM 펄스 폭은 별도 승인 없이 변경하지 않는다.

## 위험 작업

사용자 요청 없이 자동 실행하지 않는다. 요청한 코드 변경에 필요한 Arduino 업로드는 위 최신 지시와 `AGENTS.md` 절차에 따라 진행할 수 있다.

* 요청하지 않은 Arduino Mega 업로드 및 변경 없는 반복 업로드
* `SERVO_MIN_PULSE_US`, `SERVO_MAX_PULSE_US` 변경
* 서보 안전 범위 확대
* 고개 0도에서 180도 전체 범위 테스트
* 카메라 서보 회전 범위 확대
* 실제 서보를 큰 각도로 한 번에 움직이는 테스트
* Raspberry Pi 자동 실행 활성화
* Raspberry Pi 프로그램 재시작

## 고개 전체 범위 테스트

고개 0도에서 180도 이동은 현재 개발 시험 항목이며 최종 전시 동작으로 확정되지 않았다. Arduino 안전 범위가 0..180이라도 실제 기구물에서는 충돌과 과부하가 발생할 수 있다.

## 카메라 서보 테스트

카메라 서보는 PCA9685 Channel 2를 사용한다. 현재 허용 범위는 30..150도이고, 카메라 버튼을 누르면 30도, 150도, 90도 순서로 천천히 움직인다. 카메라 케이블이 고개, 팔, 외장 부품에 걸리지 않는지 먼저 확인한다.

## 전원 안전

기존 하드웨어 안전 문서 기준:

* 고토크 서보는 Raspberry Pi나 Arduino 5V 핀에서 직접 전원을 공급하지 않는다.
* 서보 외부 전원은 충분한 전류를 낼 수 있어야 한다.
* Raspberry Pi, Arduino Mega, PCA9685, 서보 외부 전원은 공통 GND를 사용한다.
* PCA9685 `VCC`와 `V+` 역할을 구분한다.
* 5V 기준 전원을 유지한다.
